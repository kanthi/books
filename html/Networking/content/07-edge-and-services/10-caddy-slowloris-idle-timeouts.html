Caddy 2.11.6: Slowloris idle timeouts and url_pattern matchers

After reading this chapter, you will be able to harden Caddy v2.11.6 edge proxies against Slowloris-style denial-of-service attacks using progress-resetting idle timeouts, configure per-route timeout overrides using the timeouts directive, and write flexible URL matching rules using the WHATWG URLPattern standard matcher.

Learning goals

  • Explain the Slowloris class of attack and how progress-resetting read/write timeouts mitigate resource exhaustion without cutting off slow, healthy clients
  • Configure global HTTP server read, write, and idle timeouts in the Caddyfile options block
  • Apply per-route read and write timeouts using the timeouts handler directive
  • Draft URL matching rules using the standard url_pattern request matcher syntax, including named capture groups and regex constraints
  • Access url_pattern capture groups in downstream directives using Caddy placeholders and CEL expressions
Note

Not run here. A local installation of Caddy v2.11.6 was not available on this environment. The Caddyfile snippets, JSON configurations, and command examples in this chapter are derived from official Caddy documentation and the Caddy v2.11.6 release notes.

This chapter does not cover Caddy deployment orchestration, TLS certificate authority integration, or custom Caddy module development in Go.

Mental model

Edge proxies facing the public internet must balance two competing goals: protecting internal worker threads and connection pools from resource exhaustion while allowing legitimate clients on slow or lossy networks to complete requests.

  Client (Attacker / Slow)                     Edge Proxy (Caddy v2.11.6)
           │                                                │
           │  ┌──────────────────────────────────────────┐  │
           │  │ Partial Headers / Body Chunk             │  │
           │  └──────────────────────────────────────────┘  │
           ├───────────────────────────────────────────────►│  Reset Idle Read Timer
           │                                                │  (Connection stays open)
           │  [Stalls / Stops sending data]                 │
           │  . . . . . . . . . . . . . . . . . . . . . . . │
           │                                                │  Idle Read Timeout Expires!
           │  ◄─────────────────────────────────────────────┤  Close Connection (TCP FIN/RST)
           │                  Socket Closed                 │

Slowloris attacks exploit connection management by opening many HTTP connections and sending HTTP headers or body payload bytes extremely slowly (for example, one byte every few seconds). Traditional fixed-duration timeouts either cut off legitimate long-running requests or permit attackers to hold sockets open indefinitely.

Caddy v2.11.6 hardened its edge defenses by updating connection read and write timeouts to reset on every successful read or write operation. If a slow client continuously makes progress, Caddy maintains the connection. If a connection stalls and fails to transfer data within the configured idle window, Caddy forcibly terminates the connection to reclaim system file descriptors and worker resources.

In addition to transport-layer defense, Caddy v2.11.6 introduced the url_pattern request matcher based on the WHATWG URLPattern specification. This standardizes request path, host, and query matching across web standards (such as browser JavaScript and runtime environments) and edge routing configs.

Feature Pre-v2.11.6 Behavior Caddy v2.11.6 Behavior
Read / Write Timeouts Absolute duration timers from connection start Timers reset on every successful socket read or write
Low Bandwidth Clients Prone to premature timeouts during large payloads Allowed as long as byte progress occurs within idle interval
Stalled Connections Held open until absolute timeout elapsed Closed immediately after the idle timeout expires without progress
Standard Path Matchers Caddy-specific wildcards (/api/*) or regex matchers Standard WHATWG url_pattern matching with named groups

Concepts — Slowloris mitigation and progress timeouts

Slowloris operates at the application layer of TCP connections. The attacker opens hundreds or thousands of connections to the HTTP proxy and sends minimal headers (such as X-a: b\r\n) at prolonged intervals to keep the request pending without completing the HTTP header block (\r\n\r\n).

Progress-resetting timers

In Caddy v2.11.6, the server HTTP transport read and write timeouts evaluate progress incrementally:

  1. Idle Read Timeout: Triggers when no new request or header bytes have been received from the socket within the designated duration. Each successful byte read from the underlying connection resets the timer.
  2. Idle Write Timeout: Triggers when the server cannot flush response bytes to the socket buffer within the designated duration. Each successful byte write resets the timer.
  3. Minimum Transfer Rates: Optionally enforces a lower bound on throughput (bytes per second). Even if a connection continuously sends bytes, it will be cut off if the average data rate falls below the minimum threshold over a sliding window.

Global options vs per-route handler tuning

Security hardening begins at the global level and is refined per route:

  • Global Server Options (servers): Defines default baseline timeouts for all incoming HTTP/HTTPS listeners.
  • Per-route Handler (timeouts): Overrides read or write timeouts for specific paths, such as allowing longer timeouts for file uploads (/upload) while enforcing tight timeouts on standard API endpoints.

Concepts — WHATWG url_pattern matchers

The url_pattern request matcher implements the WHATWG URLPattern standard syntax. This allows pattern matching across all parts of a request URL (protocol, host, port, path, and query string).

Pattern syntax conventions

url_pattern supports several matching primitives:

  • Wildcards: * matches zero or more characters.
  • Named Groups: :name captures a segment into a named placeholder.
  • Custom Regular Expressions: :name([0-9]+) constrains a named group using a regular expression pattern.
  • Wildcard Capture Groups: {*groupName} captures remaining wildcard path segments.

Captured placeholders

When a request matches a url_pattern, Caddy populates internal placeholders for downstream directives, logging, or proxy headers:

  • {http.url_pattern.pathname.group}: Accesses a captured group from the pathname component.
  • {http.url_pattern.hostname.group}: Accesses a captured group from the hostname component.

Additionally, Caddy v2.11.6 includes a corresponding url_pattern CEL (Common Expression Language) function for advanced conditional expressions in matchers.

Case — Configuring Caddy hardening and URL matching

The following examples demonstrate how to configure global timeouts, per-route timeout overrides, and url_pattern request matching in a Caddyfile.

1. Global server idle timeouts

To establish baseline protection against stalled connections, set global HTTP server timeouts in the Caddyfile options block.

{
    servers {
        timeouts {
            read_idle 5s
            write_idle 10s
            read_header 5s
        }
    }
}

example.com {
    respond "OK"
}

The shell command to test loading this configuration:

caddy validate --config Caddyfile

The output produced by the validation command:

<<OUTPUT:validate1>>

2. Per-route timeout overrides with timeouts

For endpoints that accept slow clients or large uploads (for example, /upload/*), use the timeouts handler directive to override the global defaults for specific routes.

example.com {
    # Tight timeouts for general API routes
    handle /api/* {
        timeouts {
            read 3s
            write 5s
        }
        reverse_proxy localhost:8080
    }

    # Relaxed timeouts for large file uploads
    handle /upload/* {
        timeouts {
            read 120s
            write 120s
        }
        reverse_proxy localhost:8081
    }

    # Default fallback
    handle {
        respond "Default Route"
    }
}

The command to verify formatting of the Caddyfile:

caddy fmt Caddyfile.routes

The output produced by the formatting command:

<<OUTPUT:fmt1>>

3. Matching paths and extracting parameters with url_pattern

The url_pattern matcher simplifies parameter extraction and path validation in Caddyfile routes.

example.com {
    # Match path pattern: /users/<id>/posts/<category>
    @userPosts url_pattern pathname /users/:id([0-9]+)/posts/:category

    handle @userPosts {
        # Pass captured groups to backend as custom headers
        reverse_proxy localhost:9000 {
            header_up X-User-ID {http.url_pattern.pathname.id}
            header_up X-Post-Category {http.url_pattern.pathname.category}
        }
    }

    # Match domain subdomains with wildcard hostname patterns
    @customerApp url_pattern hostname :tenant.example.com

    handle @customerApp {
        respond "Welcome to tenant: {http.url_pattern.hostname.tenant}"
    }
}

The command to validate the url_pattern syntax:

caddy validate --config Caddyfile.urlpattern

The output produced by the validation command:

<<OUTPUT:validate2>>

4. Advanced CEL matching with url_pattern

Caddy v2.11.6 supports url_pattern within CEL expressions, enabling multi-condition matching logic.

example.com {
    @complexRoute expression url_pattern('/api/v1/:resource/*', http.request.uri.path) && header({'X-Experimental': 'true'})

    handle @complexRoute {
        respond "Experimental API for resource: {http.url_pattern.pathname.resource}"
    }
}

The command to check syntax on the CEL configuration:

caddy validate --config Caddyfile.cel

Common mistakes

Mistake Impact Correct Approach
Setting fixed read timeouts too low globally Breaks legitimate slow connections on mobile networks or large POST uploads Rely on progress-resetting read_idle timeouts or override per-route using timeouts
Omitting regular expression anchors in url_pattern Regex patterns inside named groups :id([0-9]+) might match unintended path prefixes Define strict sub-patterns inside parentheses within the named group segment
Misreferencing captured placeholders Using {http.matchers.url_pattern...} instead of {http.url_pattern.<component>.<group>} yields empty values Use {http.url_pattern.pathname.<group>} or {http.url_pattern.hostname.<group>}
Confusing read_header with read_idle Slowloris attacks that stall header transmission bypass standard request timeouts Set read_header globally under servers.timeouts to bound header parsing

Key takeaways

  • Slowloris Mitigation: Caddy v2.11.6 resets read/write idle timers upon actual byte transfer, severing stalled connections while allowing slow, active transfers to complete.
  • Global & Local Timeouts: Define base timeouts inside servers.timeouts in global options, and fine-tune per-route requirements using the timeouts directive.
  • WHATWG URLPattern Compliance: The url_pattern request matcher brings standardized URL parsing syntaxes (wildcards, named groups, regex constraints) to the Caddyfile.
  • Placeholder Access: Captured URL pattern groups are directly accessible in Caddy directives via {http.url_pattern.<component>.<group>}.
