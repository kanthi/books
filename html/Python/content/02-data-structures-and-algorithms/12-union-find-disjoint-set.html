Union-find (disjoint set): path compression and union by rank

After reading this chapter, you will be able to implement an optimal Disjoint-Set Union (DSU) data structure in Python 3.13 using path compression and union by rank, analyze its near-constant amortized time complexity, and apply it to graph connectivity problems.

Mental model

The Disjoint-Set Union (DSU) data structure—often called Union-Find—tracks a partition of a set into disjoint (non-overlapping) subsets. It answers two fundamental questions efficiently:

  1. Find: Which subset or component does a specific element belong to?
  2. Union: How can we merge two separate subsets into a single set?

Instead of storing explicit lists of elements for every set, a DSU represents each subset as a tree where each node points to its parent. The root of each tree serves as the canonical representative of the entire subset.

Initial state (6 elements, 6 components):
[0]  [1]  [2]  [3]  [4]  [5]

After union(0, 1) and union(1, 2):
     0 (root)
    / \
   1   2

After union(3, 4) and union(4, 5):
     3 (root)
    / \
   4   5

Naive representation vs. optimizations

In a naive parent-pointer array implementation, merging elements can lead to tall, unbalanced trees (effectively linked lists). In the worst case, executing find() on a chain of length \(N\) takes \(O(N)\) time.

To maintain near-instant performance, two key techniques are combined:

  1. Path Compression (or Path Halving/Splitting): During a find() operation, nodes along the lookup path are re-linked directly to ancestors higher up the tree. This flattens the tree structure every time a lookup occurs.
  2. Union by Rank (or Size): When merging two trees during a union() operation, the root of the tree with smaller height (rank) is attached under the root of the taller tree. This prevents tree depth from growing unnecessarily.
Technique Finding Canonical Root Merging Sets Tree Structure
Naive Parent Array \(O(N)\) worst-case \(O(N)\) worst-case Deep, degenerate trees
Union by Rank only \(O(\log N)\) \(O(\log N)\) Balanced trees
Path Compression + Rank \(O(\alpha(N))\) amortized \(O(\alpha(N))\) amortized Extremely flat trees

Complexity intuition and the inverse Ackermann function

When both path compression and union by rank are applied, the amortized time complexity per operation (either find or union) drops to \(O(\alpha(N))\), where \(\alpha\) is the inverse Ackermann function.

The Ackermann function grows extraordinarily fast. Consequently, its inverse \(\alpha(N)\) grows extremely slowly:

  • For any practical input size \(N\) (even up to the total number of atoms in the observable universe, roughly \(10^{80}\)), \(\alpha(N) \le 4\).

For all practical engineering applications, \(O(\alpha(N))\) is treated as nearly \(O(1)\) amortized time.

Why combine both?

  • Union by rank guarantees that without path compression, tree depth never exceeds \(O(\log N)\).
  • Path compression flattens trees opportunistically on read operations.
  • Together, they ensure that tree depth stays nearly flat over any sequence of operations.

Implementation in Python 3.13

Below is a complete, self-contained Python 3.13 implementation of the DSU class featuring iterative path halving and union by rank.

"""Disjoint-set (union-find) with path compression and union by rank."""

class DSU:
    def __init__(self, n: int) -> None:
        self.parent = list(range(n))
        self.rank = [0] * n
        self.components = n

    def find(self, x: int) -> int:
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a: int, b: int) -> bool:
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1
        self.components -= 1
        return True

    def connected(self, a: int, b: int) -> bool:
        return self.find(a) == self.find(b)


if __name__ == "__main__":
    d = DSU(6)
    edges = [(0, 1), (1, 2), (3, 4), (2, 0), (4, 5)]
    for a, b in edges:
        merged = d.union(a, b)
        print(f"union({a},{b}) merged={merged} components={d.components}")
    print("connected(0,2)", d.connected(0, 2))
    print("connected(0,5)", d.connected(0, 5))
    print("finds", [d.find(i) for i in range(6)])

Worked applications

Case 1: Counting connected components in a network graph

In network engineering, determining whether servers belong to isolated subnets or counting total connected clusters can be solved by processing network edges with a DSU.

"""Count connected components and detect redundant links in a network graph."""

class DSU:
    def __init__(self, n: int) -> None:
        self.parent = list(range(n))
        self.rank = [0] * n
        self.components = n

    def find(self, x: int) -> int:
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a: int, b: int) -> bool:
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1
        self.components -= 1
        return True


def analyze_network(num_nodes: int, connections: list[tuple[int, int]]) -> None:
    dsu = DSU(num_nodes)
    redundant_edges: list[tuple[int, int]] = []

    for u, v in connections:
        if not dsu.union(u, v):
            redundant_edges.append((u, v))

    print(f"Total nodes: {num_nodes}")
    print(f"Connected components remaining: {dsu.components}")
    print(f"Redundant connections (cycles): {redundant_edges}")


if __name__ == "__main__":
    # Graph with 7 nodes (0..6) and 6 edges
    network_edges = [(0, 1), (1, 2), (2, 0), (3, 4), (4, 5), (5, 6)]
    analyze_network(7, network_edges)

Case 2: Kruskal’s algorithm sketch (Minimum Spanning Tree)

DSU is the core driver behind Kruskal’s algorithm for building Minimum Spanning Trees (MST).

The high-level algorithm proceeds as follows: 1. Sort all graph edges in non-decreasing order by weight. 2. Initialize a DSU with all vertices as separate components. 3. Iterate through sorted edges \((u, v, w)\): - If dsu.union(u, v) returns True, add the edge \((u, v)\) to the MST (it links two previously disconnected trees). - If dsu.union(u, v) returns False, skip the edge (adding it would create a cycle). 4. Stop when \(V - 1\) edges are added or all edges are processed.

Because checking and merging subsets takes near-\(O(1)\) time per edge, the overall runtime of Kruskal’s algorithm is dominated by edge sorting: \(O(E \log E)\).

Common mistakes

  1. Forgetting to update component counts: When relying on self.components for cluster counting, decrement the counter only when union() returns True (indicating two distinct components were actually merged).
  2. Modifying ranks during path compression: Path compression alters tree height without updating the rank array. This is intentional; rank serves as an upper-bound heuristic rather than an exact height measurement. Recalculating rank during compressions adds unnecessary runtime overhead.
  3. Using recursive find() without recursion limit checks: Deeply nested trees before compression can trigger Python’s RecursionError. Iterative path compression or path halving (as shown in self.parent[x] = self.parent[self.parent[x]]) completely avoids call stack overflow.
  4. Expecting dynamic node deletion: Standard Union-Find does not support removing nodes or splitting sets. Adding items and merging sets is cheap, but deleting edges requires rebuilding the DSU or using advanced offline fully-dynamic connectivity algorithms.

Key takeaways

  1. Use DSU for partition tracking: Reach for Union-Find when managing dynamic equivalence classes, counting graph components, or detecting cycles in undirected graphs.
  2. Combine compression and rank: Path compression and union by rank together yield an amortized \(O(\alpha(N)) \approx O(1)\) runtime per operation.
  3. Keep find() iterative: Prefer iterative path halving in Python to guard against maximum recursion limit errors on uncompressed paths.
  4. Prefer sets for static lookups: If set memberships do not change over time, built-in Python set or dict structures are often simpler. Use DSU when sets dynamically merge during runtime.
