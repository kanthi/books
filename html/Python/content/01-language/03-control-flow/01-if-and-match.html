if and match

After this page you can choose which code runs with if, and you can pick a shape of data with match.

Control flow chooses which code runs. if tests a condition. match picks a shape.

Every python block below is a complete file. The first line is the filename. Save it and run uv run python that_file.py.

Mental model

  if / elif / else          match / case
  ------------------        ----------------
  questions about values    questions about structure
  x > 0                     point is (x, y)
  name == "quit"            command is ["load", path]

You can write everything with if. match is clearer when the interesting part is the shape of the data (a list of two words, a number that is 0, 1, or 2, …).

if

# sign.py
def sign(n):
    if n > 0:
        return "positive"
    elif n < 0:
        return "negative"
    else:
        return "zero"


if __name__ == "__main__":
    print(sign(-2), sign(0), sign(3))
uv run python sign.py

Expected:

negative zero positive
  • if runs its block when the condition is true.
  • elif is “else if” — tried only when the previous tests failed.
  • else runs when none of the tests above succeeded.

The condition is anything truthy or falsey (see Numbers and Bool). Prefer explicit comparisons for numbers (n != 0 rather than if n) when 0 is a real value you care about.

Indentation is how Python sees the block. The lines under if must be indented the same amount (four spaces is the convention).

# even_odd.py
n = 4
if n % 2 == 0:
    print("even")
else:
    print("odd")

Expected:

even

% is remainder. Even numbers have remainder 0 when divided by 2.

Worked example: letter grades

# letter_grade.py
def letter_grade(score):
    if score >= 90:
        return "A"
    elif score >= 80:
        return "B"
    elif score >= 70:
        return "C"
    elif score >= 60:
        return "D"
    else:
        return "F"


if __name__ == "__main__":
    print(letter_grade(95), letter_grade(80), letter_grade(59))
uv run python letter_grade.py

Expected:

A B F

Order matters. If you test >= 60 first, a 95 would become a D. Test the strictest cut first.

Combining conditions

# in_range.py
score = 85
name = "Ada"

if 0 <= score <= 100:
    print("in range")

if name and name.startswith("A"):
    print("starts with A")

Expected:

in range
starts with A

and needs both sides true. or needs one side true. not flips true/false.

Python lets you write 0 <= score <= 100 the way you would on paper. You do not need score >= 0 and score <= 100, though that works too.

Ternary expression

# ternary.py
n = -3
label = "ok" if n >= 0 else "negative"
print(label)

Expected:

negative

This is an expression: it produces a value. Use it for a single value, not for two statements.

match (3.10+)

match looks at a value and asks “does it look like this?”

# describe.py
def describe(command):
    match command:
        case ["quit"]:
            return "bye"
        case ["load", path]:
            return f"loading {path}"
        case ["move", x, y] if isinstance(x, int) and isinstance(y, int):
            return f"to {x},{y}"
        case _:
            return "unknown"


if __name__ == "__main__":
    print(describe(["load", "map.txt"]))
    print(describe(["move", 2, 3]))
    print(describe(["nope"]))

Expected:

loading map.txt
to 2,3
unknown
  • case ["load", path]: means “a sequence of two items; call the second one path.”
  • path is bound (like assignment). After this case matches, you can use path.
  • if isinstance(...) after a pattern is a guard: the case only wins if that extra test is true.
  • case _: is the default. _ means “I do not need the value.”

Worked example: match on types and literals

# kind.py
def kind(value):
    match value:
        case 0 | 1 | 2:
            return "small int"
        case int():
            return "other int"
        case str() as s if s.strip() == "":
            return "blank"
        case str():
            return "text"
        case None:
            return "missing"
        case _:
            return "other"


if __name__ == "__main__":
    print(kind(1), kind(99), kind("  "), kind("hi"), kind(None))

Expected:

small int other int blank text missing

int() here is a class pattern, not a call that converts the value. 0 | 1 | 2 is an or-pattern: any of those three.

If you put case int(): before case 0 | 1 | 2:, the small integers would never be reached. First match wins.

When to stay with if

  • One or two boolean tests (if user and user.is_active)
  • Ranges (if 0 <= x < n)
  • Anything that is clearer as a sentence than as a shape

Reach for match when you are unpacking a command, a pair, or a few known variants.

Python + CS

if is selection. match is selection plus destructuring (pull the pieces out while you test the shape). You can think of it as “look at this value, name its parts, continue.” No other book required.

Pitfalls

  • case other: binds everything and swallows later cases. Put a catch-all last, or use _ if you do not need the value.
  • case ["load", path]: does not match "load" the string — only a sequence of two items.
  • == vs is: if x is None for missing values; if x == 0 for zero.
  • Forgetting the colon after if / case is a SyntaxError.
  • An if whose body is not indented is a SyntaxError or a surprising “this always runs.”

Exercises

  1. Save letter_grade.py and add a few more prints (0, 60, 100). Then, if you want, rewrite the A/B/C/D/F table as match on score // 10.
  2. Write parse.py with parse(["add", 1, 2]) and parse(["neg", 5]) using match. Reject anything else with a clear string. Run it.
  3. What does match 3: case int(x): … bind x to? Try it in the REPL, then as a tiny file.
