The 2026 Landscape

After this page you will know which 3.14 features Path A uses (match, uv) and which you can ignore until Internals (free-threading, JIT).

This page is a map of what changed around Python 3.13–3.14 so later chapters can point at it instead of repeating release notes. You can follow Path A without absorbing every row.

Mental model

  Language 3.14
       |
       +-- default CPython (GIL on)
       +-- free-threaded CPython (GIL off, official in 3.14)
       +-- optional JIT / faster eval loop (implementation detail)
       |
  Tooling
       +-- uv (install + venv + lock)
       +-- Ruff (lint/format)
       +-- ty / Pyright / mypy (types)
       +-- pytest

You can ignore free-threading and the JIT until Internals and concurrency. You should not ignore uv and 3.14 language features.

Language and stdlib you will meet early

Item Why it matters here
match / case Pattern matching — taught in Control flow
Deferred evaluation of annotations (PEP 649 / 749) Typing chapter; from __future__ import annotations is less necessary
pathlib as the default path API Errors and I/O (file paths as objects, not string glue)
Multiple interpreters (PEP 734) Internals / concurrency — isolation without a new process

Runtime: GIL and free-threading

For thirty years the Global Interpreter Lock meant one thread ran Python bytecode at a time in a process. I/O and C extensions could still overlap; CPU-bound Python threads could not.

Python 3.13 shipped an experimental free-threaded build. Python 3.14 made that build official (PEP 779): same language, optional binary without a GIL.

  default 3.14     : threads + GIL     (what `uv python install 3.14` gives you)
  free-threaded    : threads, no GIL   (opt in; some wheels may lag)

This book’s default examples use the GIL build. Internals explains both. Do not switch a production service to free-threading until you have tests and a reason.

Tooling defaults in this book

Job Default Still documented
Get an interpreter uv python install 3.14 OS packages, python.org
Isolated env uv venv + uv sync / uv add python -m venv + pip
Lint / format Ruff —
Types ty or Pyright; mypy still common —
Tests pytest unittest in the stdlib

pip install on the system Python is how environments rot. Use a venv from the first project.

Ecosystem gravity (not in the sidebar yet)

These are the usual 2026 defaults when we add domain parts later. They are not published chapters now.

Domain 2026 default we teach first Also exists
HTTP APIs FastAPI + Pydantic v2 Django, Flask, Litestar
Full web app Django FastAPI + a frontend
Data frames pandas Polars (mentioned, not required)
Classical ML scikit-learn —
Deep learning PyTorch JAX, TensorFlow/Keras
LLM apps official HTTP clients + evals frameworks that will rename themselves
NetOps Netmiko → NAPALM → Nornir Ansible for YAML-first shops
Packaging pyproject.toml + uv lock setup.py fossils

Libraries churn. Jobs (parse a table, fit a model, push a config, serve JSON) do not. Chapters teach the job, then one current library.

What we will not chase

  • Every web framework bake-off
  • Vendor-specific “agent OS” products
  • Conda vs uv religious wars (uv is the default; conda appears where scientific stacks still need it)

Exercises

  1. Run python3 --version (or uv python list after the next section). Write down major.minor.
  2. In one sentence, distinguish “Python 3.14 the language” from “free-threaded CPython.”
  3. Name one library you have already heard of (NumPy, FastAPI, pytest, …) and whether it is language, stdlib, or third-party.
