Language vs CPython

Updated

September 4, 2026

Language vs CPython vs Ecosystem

After this page you can hear someone say “Python is slow” and ask: do they mean the language, CPython, or a library?

“Python” is three different things. Mixing them up is the usual reason people argue past each other. You do not need to memorize implementation names today — just keep the three boxes apart.

Mental model

  ┌─────────────────────────────────────────┐
  │  Ecosystem   PyPI, conda, wheels, tools │
  │  ┌───────────────────────────────────┐  │
  │  │  Implementation   CPython, PyPy   │  │
  │  │  ┌─────────────────────────────┐  │  │
  │  │  │  Language   syntax, types,  │  │  │
  │  │  │  data model, stdlib spec    │  │  │
  │  │  └─────────────────────────────┘  │  │
  │  └───────────────────────────────────┘  │
  └─────────────────────────────────────────┘

1. The language

The language is the rules: what a name is, how for works, what a list guarantees, how import is supposed to find a module, which modules the standard library documents.

Those rules live in:

  • the Language Reference
  • the Standard Library docs
  • PEPs (Python Enhancement Proposals) when the rules change

If two implementations both run your file and agree on the docs, they are both “Python.”

2. The implementation (CPython)

CPython is the program that actually runs your file. It is written in C. It reads your source, compiles it to bytecode (simple instructions for a virtual machine), and runs those instructions. When you type python or uv run python, you almost always start CPython. This book’s examples assume that, on any OS.

CPython decisions that are not the language:

CPython fact Language fact
There is a GIL in the default build The language has threads
Free-threaded 3.14 builds can drop the GIL Same language, different runtime
id(x) is the object’s address id is unique for the object’s lifetime
Reference counting + a cyclic GC Objects are garbage-collected

This book’s Internals section is about CPython. Other implementations (PyPy, MicroPython) reuse the language and a large chunk of the stdlib, then change the machine.

3. The ecosystem

The ecosystem is everything you uv add or pip install: NumPy, FastAPI, pandas, Netmiko, pytest. None of that is “Python the language.” It is software written in or for Python.

The ecosystem also includes tools:

Tool Job
uv Install Python, create venvs, lock dependencies (default in this book)
pip + venv Older, still everywhere
Ruff Lint and format
ty / Pyright / mypy Type check
pytest Test

When a page says “install FastAPI,” that is ecosystem. When it says “def creates a function object,” that is language. When it says “bytecode lives in __code__,” that is CPython.

One file, three layers

# three_layers.py
# language: def, annotation syntax, f-string
def area(radius: float) -> float:
    return 3.14159 * radius * radius


# ecosystem (only if you installed it):
# import numpy as np

# CPython: this is a function object with a code object
if __name__ == "__main__":
    print(area(2))
    print(area.__code__.co_argcount)
uv run python three_layers.py

Expected:

12.56636
1

You do not need to read __code__ to use Python. You do need to know it exists so Internals has a place to stand.

Implementations you will meet

Name Where it shows up
CPython Default everywhere this book cares about
PyPy Long-running JIT workloads
MicroPython / CircuitPython Microcontrollers
Free-threaded CPython Official in 3.14 (opt-in build); same language, no GIL

Exercises

  1. Classify each item as language, CPython, or ecosystem: list.append, numpy.ndarray, the GIL, match/case, Ruff, importlib.
  2. Run python -c "import sys; print(sys.implementation)" and read the fields.
  3. Explain to a rubber duck why “Python is slow” is a statement about an implementation (and usually about your code) rather than about for loops as a notation.
