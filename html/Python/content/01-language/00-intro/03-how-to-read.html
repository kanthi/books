How to Read This Book

This is a library, not a single sitting. If you try to read every Language leaf in one go, you will stall. Pick a path on the landing page and treat the sidebar as an index, not a to-do list.

The published book is three parts: Language, Standard Library, Projects.

You do not need any other book in this library. When a page uses a terminal, a file path, or a bit of arithmetic, it explains the minimum right here.

The 3-layer practice

  Read     a short chapter (this book)
    |
    v
  Write    type the examples; change one thing; break it
    |
    v
  Ship     a tiny script, test, or note you would keep

Reading without trying the code is tourism. Shipping without reading is copy-paste. Alternate.

A REPL is the window where you type Python and see an answer immediately (next section). A script is a .py file you save and run. Path A uses both.

What a Language chapter expects

  1. Type the minimal example as a file (first line is # name.py). Run uv run python name.py. Do not only look at it.
  2. Change one name, one operator, or one argument. Predict the result. Run it again.
  3. When it fails, read the traceback from the bottom. The last line is the error type and message; the lines above are “how we got here.”
  4. Do the exercises before opening the next file.
  5. If a page has a Python + maths or Python + CS note, treat it as a small experiment you can try here. It is not homework from another book.

Paths (short)

Path First folders Stop when
A Productive Intro → Getting started → Syntax → Control → Functions → Data → Modules You can write a script that reads a file and prints a summary
B Fluent / internals Objects → Typing → Idioms → Concurrency → Internals → Standard Library You can explain a bytecode listing and what the GIL does in 3.14
C One topic One Language section, or the Standard Library map You finished that slice

Start with Path A unless you already write Python every week. You can switch paths later. You should not run two full paths in parallel the first month.

What is not in Part 01

  • Frameworks (FastAPI, Django, pandas) — later, if we add those parts
  • A Linux course, a maths course, or a networking course

Part 01 is the language, the default toolchain, and enough of how CPython runs to debug your own programs.

Tooling while you read

You have Use
Nothing yet Getting started installs uv and a 3.14 interpreter
A desktop Editors and fonts — VS Code family, Zed, Sublime, …
SSH / no GUI CLI-only setup — Helix, Neovim, tmux
A question about a builtin help(str.split) in the REPL, then the stdlib docs

Pick one editor. Do not install a dozen extensions before the first print.

How this book grows

The landing page is the syllabus for what this book will become. Some Language sections are still orientation pages (a map and a planned chapter table) until they are written. Other domains live in _planning/ until we decide how to organize them.

Exercises

  1. Choose Path A or Path B and write it on a sticky note. Do not change it for two weeks.
  2. Open the REPL (next section if you do not have one yet) and run help(print). Quit the help pager with q.
  3. Open Projects and note which first lab you will ship after Path A.
