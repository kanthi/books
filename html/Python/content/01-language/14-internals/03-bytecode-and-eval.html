Bytecode and Eval

Updated

September 2, 2026

Bytecode and Eval

CPython does not run your source line by line. It compiles a code object, then an eval loop interprets the bytecode.

Mental model

  source
    |
    v
  parse (AST)
    |
    v
  compile  →  code object
                co_code      bytes
                co_consts    20, "hello", …
                co_varnames  local names
                co_names     globals / attrs
    |
    v
  eval loop
    fetch opcode → execute → next
    (3.11+ specializing adaptive interpreter;
     3.14 also has a faster tail-call eval loop)

You do not configure this. You read it with dis when a function is surprising.

Every python block below is a complete file. Save it and run uv run python that_file.py.

Minimal example

# dis_add.py
import dis


def add(a, b):
    return a + b


if __name__ == "__main__":
    dis.dis(add)
    print(add.__code__.co_varnames, add.__code__.co_consts)
    print(add(2, 3))

You will see opcodes such as RESUME, LOAD_FAST, BINARY_OP, RETURN_VALUE. Names change between minor versions. Read the story: load a, load b, add, return — not a particular hex listing from 3.11.

compile and eval

# compile_eval.py
import dis

code = compile("2 + 3", "<demo>", "eval")
print(eval(code))
dis.dis(code)

compile(source, filename, mode) with mode "eval" (expression), "exec" (statements), or "single" (REPL). eval runs an expression; exec runs statements. Both are powerful and unsafe on untrusted strings.

Why this matters

# plus_vs_iadd.py
import dis


def loop_plus(xs):
    t = 0
    for x in xs:
        t = t + x
    return t


def loop_iadd(xs):
    t = 0
    for x in xs:
        t += x
    return t


if __name__ == "__main__":
    print(loop_plus([1, 2, 3]), loop_iadd([1, 2, 3]))
    print("--- + ---")
    dis.dis(loop_plus)
    print("--- += ---")
    dis.dis(loop_iadd)

For integers these are almost the same. For a list, t = t + [x] copies; t += [x] mutates. dis shows BINARY_OP(+) versus += in situ. Measure with timeit before you care; Internals is so you can see the difference.

Specialization (3.11+)

The adaptive interpreter rewrites some opcodes after they have seen the same types a few times (+ on two ints becomes a fast path). That is why a microbenchmark’s first milliseconds can differ from the rest. You still write normal Python.

The 3.13+ JIT (experimental) and 3.14 tail-call interpreter sit under this loop. They are CPython performance work, not a new language.

CS connection

Bytecode is a stack machine IR: load, load, binary op, store. This page is “enough to debug,” not a compilers course.

Pitfalls

  • Comparing dis output across Python versions as if opcodes were a public API.
  • eval on network input.
  • Optimizing bytecode by hand. Change the algorithm or the data layout instead.

Exercises

  1. dis.dis a function that builds a list with append and one that uses a comprehension. Note one difference.
  2. compile a tiny exec block that binds x = 1 and run it with exec into a dict you provide (exec(code, ns)).
  3. Time sum(range(10_000)) versus a Python for loop with timeit. The builtin wins; say why (C loop vs bytecode loop).
