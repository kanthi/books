Dicts and Sets

After this page you can look up a value by name, count things with a dict, and test membership with a set.

A dict maps hashable keys to values. A set is a dict that only keeps keys. Both are typically instant for add and lookup, even when they get large.

Hashable (roughly): immutable and comparable — int, str, tuple of hashables. Not list, dict, or set.

Every python block below is a complete file. The first line is the filename. Save it and run uv run python that_file.py.

Mental model

  dict   key  ──►  value
         "ada"     1815

  set    key  ──►  (present)
         "ada"

CPython 3.7+ dicts remember insertion order. Do not rely on order in a set.

Dicts

# born.py
born = {"ada": 1815, "grace": 1906}
born["alan"] = 1912
print(born["ada"])
print(born.get("nope", 0))
print(list(born))
print(list(born.values()))
for name, year in born.items():
    print(name, year)

Expected:

1815
0
['ada', 'grace', 'alan']
[1815, 1906, 1912]
ada 1815
grace 1906
alan 1912
Spelling Role
d[k] Get or set; missing key → KeyError
d.get(k, default) Safe get
d.setdefault(k, v) Get or insert v
d.pop(k) Remove and return
k in d Membership on keys

Worked example: count letters

# count_letters.py
from collections import Counter

counts = {}
for ch in "banana":
    counts[ch] = counts.get(ch, 0) + 1
print(counts)
print(Counter("banana"))

Expected:

{'b': 1, 'a': 3, 'n': 2}
Counter({'a': 3, 'n': 2, 'b': 1})

d[k] += 1 fails if k is missing (KeyError). .get(ch, 0) supplies a zero for the first sighting. Use Counter when you are actually counting.

Sets

# seen.py
seen = {"ada", "grace"}
seen.add("alan")
print("ada" in seen)
print(seen & {"ada", "linus"})
print(seen | {"linus"})
print(seen - {"grace"})
print(set([1, 1, 2, 3]))
print(type({}), type(set()))

Expected (set order may differ):

True
{'ada'}
{'ada', 'grace', 'alan', 'linus'}
{'ada', 'alan'}
{1, 2, 3}
<class 'dict'> <class 'set'>

Empty set is set(), not {} — {} is an empty dict. Sets drop duplicates. They are the right type for “have I already seen this?”

Worked example: names in both lists

# both_names.py
lab = ["ada", "grace", "alan"]
class_list = ["grace", "linus", "ada"]
both = set(lab) & set(class_list)
print(both)
print([name for name in lab if name in set(class_list)])

Expected (set order may differ on the first line):

{'grace', 'ada'}
['ada', 'grace']

Converting to sets makes membership cheap and drops duplicates. The list comprehension keeps the original order of lab.

What can be a key

# hashable_key.py
ok = {("ada", 1815): "ok"}
print(ok[("ada", 1815)])
try:
    bad = {["ada"]: "no"}
except TypeError as err:
    print(type(err).__name__, err)

Expected:

ok
TypeError unhashable type: 'list'

If you mutate an object that is already a key, the dict cannot find it again. That is why only immutables are allowed.

dict vs list vs set — pick

Question Type
Ordered collection, duplicates ok list
Fixed record / pair tuple
Lookup by name dict
Membership only set

If you catch yourself writing for row in rows: if row[0] == name, you probably wanted a dict keyed by name.

Python + CS / maths

A dict is a hash table: turn the key into a number, jump to a slot. A set’s & | - are operations you can try on two small sets — Python showing membership, not a lecture on relations.

# set_ops.py
a = {1, 2, 3}
b = {3, 4}
print("intersection", a & b)
print("union       ", a | b)
print("difference  ", a - b)

Expected:

intersection {3}
union        {1, 2, 3, 4}
difference   {1, 2}

CPython’s dict is also how objects store attributes (Internals). That is why obj.x and d["x"] feel similar.

Pitfalls

# missing_key.py
d = {}
try:
    d["a"] += 1
except KeyError:
    d["a"] = d.get("a", 0) + 1
print(d)

Expected:

{'a': 1}
  • if key in d.values() is a linear scan. Membership is for keys.
  • Building a set of lists: convert each list to a tuple first.
  • Do not write tests that depend on set order.
