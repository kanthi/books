Editors and Fonts

After this page you can pick one editor, point it at this book’s toolchain (uv + a project .venv + Ruff), and set a font you can read for hours.

This page is for macOS and Linux with a graphical desktop. If you work over SSH or without a GUI, skip to CLI-only setup. Windows notes are short; the same VS Code / Cursor settings apply.

You do not need another book. An editor is the program where you type .py files. The interpreter is still uv run python from Install. Mixing those two up is the usual “it runs here but not there” bug.

Mental model

  you type in an editor
         |
         v
  a .py file on disk     (UTF-8, 4 spaces)
         |
         v
  uv run python file.py  ← the interpreter this book uses

  optional extras (nice, not required on day one)
    language server  →  completions, “go to definition”, red squiggles
    Ruff             →  format and lint on save
    .venv            →  the editor must pick *this* project’s Python

Any program that can save a .py file is enough for Path A. The rest of this page is so the extras do not fight you.

What every setup must do

Job Healthy result
Save UTF-8, Unix line endings (\n), spaces not tabs
Run A terminal can cd to the project and uv run python hello.py
Interpreter Completions come from .venv, not /usr/bin/python3
Format Ruff, when you have a pyproject.toml

Pick one editor. Do not install two language servers that both format on save.

A file to open in every editor

Save this as hello_env.py in ~/src/py-lab (create that folder with uv init if you have not):

# hello_env.py
import sys

print(sys.version.split()[0])
print(sys.executable)
cd ~/src/py-lab
uv run python hello_env.py

You want 3.14.x and a path that contains .venv or uv’s cache — not a mystery system Python. After you configure the editor, run the same file from the editor’s Run / terminal and compare the two paths.

Fonts (do this once, for every editor)

Code is easier to read when 0/O, 1/l/I, and =/- cannot be confused. Use a monospace font (every character the same width). Do not use a proportional font (Times, Arial, the system UI font) for Python.

Fonts that work well for Python

Font Why people pick it Ligatures Notes
JetBrains Mono Default recommendation in this book optional Clear 0/O, free, everywhere
Cascadia Code / Cascadia Mono Ships with Windows Terminal; also on macOS/Linux Code has them; Mono does not Good if you already have it
IBM Plex Mono Slightly softer, still unambiguous no Nice on high-DPI screens
Iosevka Narrow — more columns on a laptop optional Tweakable if you build it
Commit Mono Designed for reading diffs optional Very even weights
Fira Code Famous ligatures (!= becomes ≠) yes Only if you like ligatures
Hack / Source Code Pro Old reliable no Fine if already installed

Ligatures merge character pairs (==, ->, !=) into one glyph. They do not change the file. This book’s listings use the raw characters. If ligatures confuse you, pick a font without them, or turn them off.

Nerd Fonts (JetBrainsMono Nerd Font, …) add icons for status lines and file trees. Useful in Neovim / some terminals. Not required in VS Code or Zed.

Size: 13–15 pt on a laptop, 14–16 on a large monitor. Add a little line height if the font feels cramped.

Install a font (macOS)

Homebrew (cask names as of 2026):

brew install --cask font-jetbrains-mono
# optional icons for CLI editors:
# brew install --cask font-jetbrains-mono-nerd-font

Or download from JetBrains Mono, open the .ttf files, click Install.

Install a font (Linux)

Debian / Ubuntu:

sudo apt update
sudo apt install fonts-jetbrains-mono fonts-firacode

Fedora:

sudo dnf install jetbrains-mono-fonts fira-code-fonts

Arch:

sudo pacman -S ttf-jetbrains-mono ttf-fira-code

Then log out and back in (or restart the editor) so the font list refreshes. In GNOME you can also drop .ttf files into ~/.local/share/fonts/ and run fc-cache -f.

VS Code (and Cursor, Antigravity, Windsurf, VSCodium)

Visual Studio Code is the common desktop editor for Python. Cursor, Google Antigravity IDE, Windsurf, and several others are VS Code–shaped: same settings keys, same Command Palette (Ctrl+Shift+P / Cmd+Shift+P), usually the same extension IDs. VSCodium is VS Code without Microsoft branding or telemetry; extensions come from Open VSX, not the Microsoft Marketplace.

Antigravity (Google, late 2025+) has more than one surface. Use Antigravity IDE (the VS Code–like editor) for this page. The agent-only desktop is not a Python editor.

Install the app

macOS:

brew install --cask visual-studio-code
# or: brew install --cask cursor

Or download from code.visualstudio.com.

Linux: prefer the vendor .deb / .rpm / official tarball so code lands on PATH. Flatpak works; the integrated terminal then needs Flatpak’s extra permissions to see uv in ~/.local/bin.

Open the folder ~/src/py-lab, not a single file. File → Open Folder. Language servers attach to a folder.

Extensions (keep this short)

In the Extensions view, install:

Extension Publisher / id Job
Python Microsoft ms-python.python Interpreter picker, run, tests
Ruff Astral charliermarsh.ruff Lint + format

The Python extension pulls Pylance (completions / type hints) and Python Debugger (debugpy). You do not need Pylint, Flake8, Black, autopep8, or isort — Ruff covers that job.

Cursor / Windsurf / Antigravity IDE: search the same names. If an ID is missing, install the Open VSX build of Ruff and a Pyright/Pylance-compatible language server.

Point the editor at the project interpreter

  1. Ctrl+Shift+P / Cmd+Shift+P
  2. Python: Select Interpreter
  3. Choose ./.venv/bin/python (uv creates .venv on uv sync / uv add)

If .venv is missing:

cd ~/src/py-lab
uv sync

Status bar (bottom right) should show 3.14.x ('.venv': venv) or similar.

User settings.json

Command Palette → Preferences: Open User Settings (JSON). This is a complete file you can paste. It sets the font, Ruff on save, and Python defaults. It does not pin a single machine’s .venv path (that is per-workspace).

{
  "editor.fontFamily": "JetBrains Mono, Menlo, monospace",
  "editor.fontSize": 14,
  "editor.lineHeight": 22,
  "editor.fontLigatures": false,
  "editor.tabSize": 4,
  "editor.insertSpaces": true,
  "editor.rulers": [88],
  "editor.formatOnSave": true,
  "files.eol": "\n",
  "files.insertFinalNewline": true,
  "files.trimTrailingWhitespace": true,
  "python.languageServer": "Pylance",
  "python.analysis.typeCheckingMode": "off",
  "[python]": {
    "editor.defaultFormatter": "charliermarsh.ruff",
    "editor.codeActionsOnSave": {
      "source.fixAll.ruff": "explicit",
      "source.organizeImports.ruff": "explicit"
    }
  }
}

typeCheckingMode is off for Path A. Turn it to basic when you reach the Typing section.

Optional workspace file .vscode/settings.json (commit this if the team agrees):

{
  "python.defaultInterpreterPath": "${workspaceFolder}/.venv/bin/python"
}

Where each fork keeps settings

App macOS user settings Linux user settings
VS Code ~/Library/Application Support/Code/User/settings.json ~/.config/Code/User/settings.json
Cursor …/Cursor/User/settings.json ~/.config/Cursor/User/settings.json
VSCodium …/VSCodium/User/settings.json ~/.config/VSCodium/User/settings.json
Antigravity IDE / Windsurf same pattern under that app’s name same

The JSON keys above are the same. Do not copy a whole User/ folder between forks — only the settings you understand.

Integrated terminal

Terminal → New Terminal. Check:

which uv
uv run python -c "import sys; print(sys.executable)"

If uv is “not found,” your GUI app was started without the same PATH as the terminal. On macOS, launch from a terminal once (code . or cursor .) or add ~/.local/bin (uv’s default) to the shell file the GUI reads. On Linux, put a symlink in /usr/local/bin or fix the desktop file’s environment.

Run and debug

  • Run the current file: the ▶ button, or right-click → Run Python File in Terminal. Prefer a terminal tab: uv run python hello_env.py so you always hit the project interpreter.
  • Breakpoints: click left of a line number, then Run → Start Debugging (F5). The debugger uses debugpy; pick the .venv interpreter first.

Zed

Zed is a native editor (not a VS Code fork). Python works without an extension pack. Recent Zed uses basedpyright for navigation and Ruff for format/lint. It discovers uv / .venv toolchains itself.

macOS:

brew install --cask zed

Linux: see zed.dev/download. Then from a project:

cd ~/src/py-lab
zed .

Open Settings (Cmd+, / Ctrl+,) → open settings.json. Complete starter:

{
  "buffer_font_family": "JetBrains Mono",
  "buffer_font_size": 14,
  "buffer_font_features": {
    "calt": false
  },
  "tab_size": 4,
  "hard_tabs": false,
  "format_on_save": "on",
  "languages": {
    "Python": {
      "language_servers": ["basedpyright", "ruff"],
      "formatter": {
        "language_server": {
          "name": "ruff"
        }
      },
      "code_actions_on_format": {
        "source.organizeImports.ruff": true
      }
    }
  }
}

calt: false turns ligatures off. If you want Fira Code ligatures, set "buffer_font_family": "Fira Code" and "calt": true.

If import resolution is wrong, open the toolchain selector and pick .venv. Zed activates that venv in new integrated terminals.

Optional: later you can swap basedpyright for ty (Astral) by putting "ty" first and "!basedpyright" in language_servers. Path A does not need that.

Sublime Text

Sublime Text 4 is fast and stays out of the way. Language intelligence is a plugin, not built in.

  1. Install Sublime (macOS: brew install --cask sublime-text; Linux: vendor repo).
  2. Install Package Control (Tools → Install Package Control).
  3. Command Palette (Cmd+Shift+P / Ctrl+Shift+P) → Package Control: Install Package, then:
    • LSP
    • LSP-pyright (or LSP-basedpyright)
    • Ruff (or LSP-ruff)
    • Terminus (an in-editor terminal)

Preferences → Settings — complete user file:

{
  "font_face": "JetBrains Mono",
  "font_size": 14,
  "font_options": ["no_calt"],
  "translate_tabs_to_spaces": true,
  "tab_size": 4,
  "rulers": [88],
  "ensure_newline_at_eof_on_save": true,
  "trim_trailing_white_space_on_save": "all",
  "default_line_ending": "unix"
}

Point Pyright at the project venv. Project → Save Project As… then edit the .sublime-project file:

{
  "folders": [{ "path": "." }],
  "settings": {
    "LSP": {
      "LSP-pyright": {
        "settings": {
          "python.pythonPath": "${folder}/.venv/bin/python"
        }
      }
    }
  }
}

Run from Terminus or an external terminal: uv run python hello_env.py.

Other popular desktop editors

You only need one. This table is so the names are not mysteries.

Editor Where it fits Python setup in one line
PyCharm Community Full IDE: debugger, refactors, Django later New Project → existing ~/src/py-lab → interpreter .venv (uv). Enable Ruff plugin. Font: Settings → Editor → Font.
PyCharm Professional Same + web/DB tools Same interpreter story; skip until you need those tools.
VSCodium VS Code without Microsoft Marketplace Same settings.json; get Python + Ruff from Open VSX.
Cursor VS Code + AI chat/inline Same Python + Ruff extensions and settings as VS Code. Still pick .venv.
Windsurf Another VS Code–shaped AI IDE Same.
Antigravity IDE Google’s VS Code–shaped IDE Same settings keys; install Python + Ruff if the catalog has them.
Nova (macOS) Native Mac editor Install a Python / LSP extension; set interpreter to .venv/bin/python.
Kate / GNOME Text Editor / Geany (Linux) Distro defaults Fine for typing. Add an LSP plugin if you want squiggles; or just use the terminal.
IDLE Ships with python.org Fine for a 10-line experiment. Do not stay there.
JupyterLab / VS Code notebooks Data later Not Path A. .py files first.

Emacs, Neovim, Helix, and nano live on CLI-only setup — they also work in a GUI terminal.

Shared habits (any editor)

  • One folder = one project. Open ~/src/py-lab, not your entire home directory.
  • Format on save with Ruff once you have a pyproject.toml. Until then, four spaces and a newline at the end of the file are enough.
  • Do not commit .venv, __pycache__, or editor crash dumps. .vscode/settings.json is optional; .idea/ (PyCharm) is usually gitignored.
  • Two Pythons — the one the editor uses for completions, and the one the terminal runs — must match. When they disagree, print sys.executable in both places.

Pitfalls

  • Opening a single file instead of a folder: the language server never sees .venv.
  • Microsoft Pylint + Ruff both enabled: double squiggles. Disable Pylint.
  • Formatters fighting: Black and Ruff on save. Pick Ruff.
  • Ligatures that make == look like a single character when you are still learning. Turn them off for a month.
  • A GUI app that cannot see uv because PATH was only set in ~/.bashrc and you launched from the Dock. Launch once from a terminal, or add ~/.local/bin to a login-shell file (~/.zprofile on macOS zsh, ~/.profile on many Linux desktops).

Exercises

  1. Install JetBrains Mono (or name the monospace font you already use). Set it in your editor. Type 0O 1lI == != and check you can tell them apart.
  2. Open ~/src/py-lab as a folder. Run hello_env.py from the editor terminal. Confirm sys.executable matches uv run python hello_env.py.
  3. Enable format-on-save with Ruff. Mess up the spacing in hello_env.py, save, and watch it snap back.
