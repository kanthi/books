CLI-Only Setup

After this page you can edit and run Python on a Linux or macOS machine that has no desktop — SSH into a server, a VM, or a laptop you use only in the terminal.

This book is not a Linux course. You need four programs: a shell (already there), uv, a terminal editor, and a way to run uv run python file.py. Optional: a multiplexer so a disconnect does not kill the session.

If you have a graphical desktop, you can still use everything here inside the editor’s terminal. The editors and fonts page stays valid.

Mental model

  your keyboard
       |
       v
  terminal app   (Kitty, Ghostty, iTerm, Linux console, SSH)
       |
       v
  shell          (bash, zsh, fish)  — reads PATH
       |
       +-- uv / python
       +-- editor (nano, micro, Helix, Neovim, Vim, Emacs)
       +-- optional tmux

The terminal app draws letters. The shell runs commands. The editor changes files. Mixing “the terminal is broken” with “Python is broken” wastes an afternoon — print echo $PATH and uv run python -V first.

0. Interpreter (same as Install)

On the remote or local machine:

curl -LsSf https://astral.sh/uv/install.sh | sh

Log out and back in, or source the line the installer printed. Then:

uv python install 3.14
mkdir -p ~/src/py-lab && cd ~/src/py-lab
uv init --python 3.14
uv run python -V

uv usually lands in ~/.local/bin. If uv is not found after install:

export PATH="$HOME/.local/bin:$PATH"

Put that line in ~/.bashrc (bash) or ~/.zshrc (zsh) so every new login has it. That is the whole PATH lesson this page needs.

1. Fonts in a terminal (when you do have a window)

On a headless server you cannot change the font — use what the SSH client on your laptop uses. Set JetBrains Mono (or JetBrainsMono Nerd Font) in:

Terminal Where
Ghostty font-family = JetBrains Mono in ~/.config/ghostty/config
Kitty font_family JetBrains Mono in ~/.config/kitty/kitty.conf
WezTerm font = wezterm.font("JetBrains Mono") in ~/.wezterm.lua
Alacritty font.normal.family: JetBrains Mono in ~/.config/alacritty/alacritty.toml
iTerm2 (macOS) Settings → Profiles → Text
GNOME Console / Terminal Preferences → Profile → Text
Linux TTY (no GUI at all) skip; the firmware font is fine for Path A

Ligatures in a terminal are optional. Nerd Fonts matter only if your Neovim theme draws icons.

2. Choose an editor (pick one)

Editor Install (typical) Why pick it
nano already on most Linux Keys are on the screen. Fine for 30 lines.
micro see below nano-like, mouse, syntax highlight
Helix see below Modal, LSP built in — best “one binary” CLI IDE
Neovim sudo apt install neovim Modal, huge ecosystem; you must add LSP yourself
Vim already there as vi / vim Same family as Neovim; older defaults
Emacs sudo apt install emacs-nox Lisp-configurable; emacs-nox is the no-X build

emacs-nox and vim-nox are the “no GUI toolkit” packages. Use those on a server.

nano (lowest friction)

nano hello_env.py

Ctrl-O save, Ctrl-X exit. Tabs: put this in ~/.nanorc:

set tabsize 4
set tabstospaces
set linenumbers
set autoindent

Then run uv run python hello_env.py in the same directory.

micro

# Linux (official tarball pattern — check micro-editor.github.io)
curl https://getmic.ro | bash
sudo mv micro /usr/local/bin/

macOS: brew install micro. Open micro hello_env.py. Ctrl-S save. Optional ~/.config/micro/settings.json:

{
  "tabsize": 4,
  "tabstospaces": true,
  "rmtrailingws": true,
  "eofnewline": true
}

Helix (recommended CLI “IDE”)

Helix talks to language servers without a plugin manager.

macOS: brew install helix
Linux: vendor package or helix-editor.com.

Put the language servers on PATH with uv (once per machine):

uv tool install ruff
uv tool install basedpyright
# ensure uv's tool bin is on PATH (usually ~/.local/bin)
uv tool update-shell

Complete Helix language file — save as ~/.config/helix/languages.toml:

[[language]]
name = "python"
language-servers = ["basedpyright", "ruff"]
auto-format = true
formatter = { command = "ruff", args = ["format", "-"] }

[language-server.ruff]
command = "ruff"
args = ["server"]

[language-server.basedpyright]
command = "basedpyright-langserver"
args = ["--stdio"]

Complete Helix user file — ~/.config/helix/config.toml:

theme = "onelight"

[editor]
line-number = "relative"
cursorline = true
bufferline = "multiple"

[editor.lsp]
display-inlay-hints = false

[editor.file-picker]
hidden = false

[editor.indent-guides]
render = true

Use a dark theme (onedark, base16_default_dark) if your terminal is dark.

cd ~/src/py-lab
hx hello_env.py

:fmt formats. :w saves. :q quits. Space-k shows the hover (if the LSP started — check :log-open if not).

Helix / basedpyright find .venv when you open the project directory (hx .) rather than a file from $HOME.

Neovim (if you already speak Vim)

A full Neovim distribution (LazyVim, NvChad, kickstart.nvim) is optional later. For Path A, Debian/Ubuntu neovim plus one small config is enough.

Save as ~/.config/nvim/init.lua (Neovim 0.11+ can talk to LSP without a plugin; this file stays small):

-- ~/.config/nvim/init.lua
vim.opt.number = true
vim.opt.relativenumber = true
vim.opt.expandtab = true
vim.opt.shiftwidth = 4
vim.opt.tabstop = 4
vim.opt.list = true

-- Format with Ruff on save when the binary exists
vim.api.nvim_create_autocmd("BufWritePre", {
  pattern = "*.py",
  callback = function()
    if vim.fn.executable("ruff") == 1 then
      vim.cmd("silent !ruff format %")
      vim.cmd("edit")
    end
  end,
})
cd ~/src/py-lab
nvim hello_env.py

:w save, :q quit, i insert, Esc back to normal. If you want go-to-definition, install Helix or add basedpyright to Neovim’s LSP later — do not block Path A on a plugin manager.

Emacs (no X)

sudo apt install emacs-nox   # Debian/Ubuntu
# macOS: brew install emacs

emacs hello_env.py. Ctrl-X Ctrl-S save, Ctrl-X Ctrl-C exit. Spaces:

;; ~/.emacs.d/init.el
(setq-default indent-tabs-mode nil)
(setq-default tab-width 4)
(add-hook 'python-mode-hook (lambda () (setq python-indent-offset 4)))

M-x eglot (Emacs 29+) starts a language server if basedpyright-langserver is on PATH (uv tool install basedpyright).

3. tmux (SSH that survives a drop)

If you work over SSH, start tmux so a laptop sleep does not kill the editor.

sudo apt install tmux    # or: brew install tmux
tmux new -s py

Detach: Ctrl-B then d. Reattach: tmux attach -t py. That is enough. Nested tmux-inside-tmux is how people get stuck — one layer.

4. Run, lint, test — no GUI required

From ~/src/py-lab:

uv run python hello_env.py
uv run python -c "import sys; print(sys.executable)"
uv add --dev ruff pytest
uv run ruff format .
uv run ruff check .
uv run pytest

There is no “Run button.” The commands are the run button. Project layout will add pytest properly; the lines above are enough to prove the machine works.

5. Remote folders vs remote terminals

Three common shapes:

Shape What you do
SSH + editor on the server ssh host, then Helix/Neovim/nano on the remote disk. This page.
SSH + editor on the laptop VS Code / Cursor / Zed Remote SSH (or tramp in Emacs) edits remote files in a GUI. Use Editors and fonts locally; uv still lives on the server.
No Python on the laptop Dev container / Codespaces later. Not Path A.

Do not edit the same file in two places without noticing. One editor, one folder.

Complete check (copy this)

# check.sh — run from ~/src/py-lab
set -e
command -v uv
uv run python -c "import sys; print(sys.version); print(sys.executable)"
test -f hello_env.py && uv run python hello_env.py

Expected: a 3.14 version line and a path you recognize. If command -v uv fails, fix PATH before touching the editor.

Pitfalls

  • Installing Python with apt only and never uv: you get an older interpreter and no project venv. Fine for “is Python here?”; not this book’s default.
  • Editing as root (sudo nano). Files become unwritable as you. Use your user.
  • Windows line endings (\r\n) after copying from a laptop. uv run python still runs; Ruff will nag. ruff format rewrites them if you configure it; or sed -i 's/\r$//' file.py.
  • Two venvs: one you created with python3 -m venv and one with uv. Pick uv; delete the extra .venv and uv sync.
  • Helix LSP “does nothing”: basedpyright-langserver is not on PATH. command -v basedpyright-langserver must print a path.

Exercises

  1. On the machine you will actually use, run the check.sh snippet (or the same commands by hand). Write down sys.executable.
  2. Open hello_env.py in nano or Helix, change the first print, save, run it. Change it back.
  3. If you SSH: start tmux, detach, log out, log in, tmux attach. Confirm the shell is still in ~/src/py-lab.
