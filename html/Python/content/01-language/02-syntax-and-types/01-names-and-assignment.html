Names and Assignment

After this page you can look at x = 20 and draw what Python actually did — and you will know why b = a does not copy a list.

In Python a name is a label on an object, not a box that holds a value. Assignment sticks a label on something that already exists.

Mental model

  n = 20          # find (or create) the int 20; attach the name n

      n ──────►  20

  n = n + 1       # compute 21; move the name n

      n ──────►  21
                 20   (old int, no name, will be cleaned up)

Think of sticky notes, not Tupperware. The number 20 is an object. The name n is a sticky note on it. n = n + 1 does not scratch out the 20 and write 21 inside the same box. It computes a new object 21 and moves the sticky note.

This is why b = a does not copy a list. Both sticky notes point at the same object.

Every python block below is a complete file. The first line is the filename. Save it and run uv run python that_file.py.

Minimal example

# labels.py
celsius = 20
label = celsius
print(celsius, label)
celsius = 21
print(celsius, label)

Expected:

20 20
21 20

Integers never change. Rebinding celsius does not touch label. label still points at 20.

Type it in the REPL if the picture is fuzzy. Watch the two prints.

Assignment is not math

# increment.py
x = 3
x = x + 1     # legal: the right-hand side uses the old binding first
print(x)
print(x == 4)

Expected:

4
True

= is not equality. Equality is ==.

>>> x = 3
>>> x == 3
True
>>> x == 4
False

= means “bind this name.” == means “are these values equal?” Mixing them up is the first week’s classic SyntaxError or a condition that is always true.

Several names, one statement

# several_names.py
a, b = 1, 2
print(a, b)
a, b = b, a       # swap — the right-hand side is fully evaluated first
print(a, b)
x = y = 0         # both names on the same 0
print(x, y)

Expected:

1 2
2 1
0 0

Worked example: swap without a temporary

In many languages you write tmp = a; a = b; b = tmp. In Python the right-hand side b, a is built first (a pair of values), then unpacked onto the left.

# swap.py
left, right = "tea", "coffee"
left, right = right, left
print(left, right)

Expected:

coffee tea

Unpacking is the same idea: match a structure on the right to names on the left. Data structures will go further.

What is a legal name

  ok     :  celsius, c_to_f, _hidden, X2, name2
  not ok :  2x, celsius-temp, class, def, a name

Rules you can remember:

  • Start with a letter or _, then letters, digits, or _.
  • Names are case-sensitive: Temp and temp are different names.
  • Some words are keywords (if, def, class, return, …). They are already spoken for.

Convention: snake_case for functions and variables (c_to_f, user_name), CapWords for classes (Point, HttpError). Ruff will nag you later; start the habit now.

>>> help("keywords")

That lists every keyword. Try assigning to class and read the error.

Mutation vs rebinding (preview)

# two_names.py
nums = [1, 2, 3]
also = nums
also.append(4)
print(nums)
print(also is nums)

Expected:

[1, 2, 3, 4]
True

append mutates the list (changes the object in place). also = [0] would rebind the name also and leave nums alone.

  After nums = [1, 2, 3] and also = nums:

      nums ──►  [1, 2, 3]
      also ──┘

  After also.append(4):

      nums ──►  [1, 2, 3, 4]
      also ──┘

  After also = [0]:

      nums ──►  [1, 2, 3, 4]
      also ──►  [0]

If a result surprises you, draw the arrows. Lists and tuples will spend more time here.

Worked example: two empty lists

# two_lists.py
x = y = []      # one list, two names — usually a mistake
x.append(1)
print("shared", y)

x, y = [], []   # two lists
x.append(1)
print("separate", y)

Expected:

shared [1]
separate []

Using a name too early

>>> print(score)
Traceback (most recent call last):
  ...
NameError: name 'score' is not defined

NameError means “there is no sticky note with that word.” Either you have not assigned it yet, or you typo’d (celcius vs celsius).

Python + CS

This is the environment in a programming-language sense: a mapping from names to objects. Functions will nest those mappings (scope). You can see the idea without another book: after n = 20, the name n is in the current environment.

Pitfalls

  • Using a name before assignment: NameError.
  • A typo creates a new name (celcius = 20) and the old one never updates.
  • x = y = [] — both names, one list. For two empty lists use x, y = [], [].
  • = in a condition (if x = 3) is a SyntaxError. You meant ==.

Exercises

  1. Draw arrows for a = [1]; b = a; a = [2]. What is b? Run it and check.
  2. Swap left and right in one line without a temporary name.
  3. Find three words that cannot be names because they are keywords (help("keywords")). Try assigning to one and read the error.
