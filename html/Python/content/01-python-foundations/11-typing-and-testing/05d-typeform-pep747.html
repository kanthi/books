TypeForm: Typing Functions That Take Types as Values (PEP 747)

Thesis

Validators, converters and runtime checkers all take a type as an ordinary argument: TypeAdapter(int | str), check_type(value, list[int]), structure(data, Literal["r", "w"]). Until Python 3.15 there was no honest annotation for that parameter. type[T] only admits class objects, so int | None and Literal["r"] are rejected. object admits everything and throws away the T, so the return type comes back as Any or Unknown. PEP 747 adds typing.TypeForm[T], which is the type of the runtime value of any valid type expression that spells a type assignable to T. The checker can now solve T from the form you pass, and the runtime function receives exactly the object it always did. This chapter builds a small runtime checker on top of it and runs mypy and pyright against both the happy path and the cases the PEP says must be rejected.

Mental model

There are three rules to keep in mind:

  1. What is a type form? It is whatever a valid type expression evaluates to at runtime: a class, a types.UnionType, a typing._LiteralGenericAlias, a GenericAlias, None, or even a string such as "set[str]". TypeForm[T] is the set of such objects whose type is assignable to T. So TypeForm[str | None] accepts str, None, Optional[str] and "str | None", but not str | int and not list[str | None].
  2. The parameter is covariant, and type[T] is a subtype. TypeForm[int] is assignable to TypeForm[int | str]. Every existing type[C] value is already a TypeForm[C], so widening a parameter from type[T] to TypeForm[T] breaks no callers.
  3. It is a checker-side promise. The checker validates the expression with the same grammar it uses for annotations, so a call like type(1), a tuple or a qualifier such as ClassVar[int] is rejected. At runtime nothing changes. TypeForm(x) simply returns x, and your function still has to interpret the object with get_origin and get_args.

TypeForm without arguments means TypeForm[Any]. TypeForm[object] is “any valid type form at all”. Introspection helpers like typing.get_origin keep their object parameter, because they also accept annotation expressions (ClassVar[int], Final) that are not type expressions.

Worked example

The lab ran on CPython 3.15.0 with mypy 2.4.1 (where TypeForm is listed under COMPLETE_FEATURES, so no flag is needed), pyright 1.1.414 and pydantic 2.14.2.

A runtime checker with an honest signature

is_assignable returns TypeIs[T], so a successful check narrows the argument to the type the form spells. checkcast returns T or raises. The body is ordinary runtime introspection. Only the two signatures depend on PEP 747.

"""A tiny runtime checker whose signature finally says what it does: PEP 747 TypeForm (Python 3.15)."""
import types
from typing import Annotated, Any, Literal, TypeForm, TypeIs, Union, get_args, get_origin

def is_assignable[T](value: object, typx: TypeForm[T]) -> TypeIs[T]:
    """Does `value` inhabit the type that `typx` spells? Handles the common forms."""
    if isinstance(typx, str):                       # "list[int]": a quoted type expression
        typx = eval(typx, vars(__import__("typing")) | vars(__import__("builtins")))
    if typx is Any or typx is object: return True
    if typx is None or typx is type(None): return value is None
    origin, args = get_origin(typx), get_args(typx)
    if origin is Annotated: return is_assignable(value, args[0])
    if origin in (Union, types.UnionType): return any(is_assignable(value, a) for a in args)
    if origin is Literal: return any(value == a and type(value) is type(a) for a in args)
    if origin is list: return isinstance(value, list) and all(is_assignable(v, args[0]) for v in value)
    if origin is dict:
        return isinstance(value, dict) and all(is_assignable(k, args[0]) and is_assignable(v, args[1]) for k, v in value.items())
    if origin is tuple:
        if len(args) == 2 and args[1] is Ellipsis:
            return isinstance(value, tuple) and all(is_assignable(v, args[0]) for v in value)
        return isinstance(value, tuple) and len(value) == len(args) and all(map(is_assignable, value, args))
    if isinstance(typx, type): return isinstance(value, typx) and not (typx is int and isinstance(value, bool))
    raise TypeError(f"unsupported type form: {typx!r}")

def checkcast[T](typx: TypeForm[T], value: object) -> T:
    if is_assignable(value, typx): return value
    raise TypeError(f"{value!r} is not assignable to {typx!r}")

Using it: what the checkers infer

from typing import Annotated, Literal, TypeForm, reveal_type
from pydantic import TypeAdapter
from typeforms import checkcast, is_assignable

def handle(raw: object) -> None:
    if is_assignable(raw, list[int] | None):         # TypeIs narrows to the type the form spells
        reveal_type(raw)
    mode = checkcast(Literal["r", "w"], "r")
    reveal_type(mode)
    port = checkcast(Annotated[int, "1-65535"], 8080)
    reveal_type(port)

handle([1, 2, 3])

# Explicit evaluation: TypeForm(...) returns its argument unchanged at runtime, but the checker validates it.
spec = TypeForm(dict[str, tuple[int, ...]])
reveal_type(spec)
print(spec, is_assignable({"a": (1, 2)}, spec), is_assignable({"a": [1, 2]}, spec))

# Pydantic 2.14 annotates TypeAdapter.__init__ with TypeForm[T], so the validated result is typed.
ta = TypeAdapter(int | str)
reveal_type(ta.validate_python("7"))
for v in [[1, 2], None, [1, "x"], True, (1,)]:
    print(f"{v!r:10} list[int] | None -> {is_assignable(v, list[int] | None)}")
print(is_assignable(True, int), is_assignable(1, Literal[True]), is_assignable("w", "Literal['r', 'w']"))

The cases that must fail

from typing import ClassVar, Literal, TypeForm
from typeforms import checkcast

def trycast_old[T](typx: type[T], value: object) -> T | None: ...

trycast_old(str, "hi")                     # fine: a class is a type[T]
trycast_old(str | None, "hi")              # rejected: a union is not a class
trycast_old(Literal["hi"], "hi")           # rejected: Literal is not a class

ok: TypeForm[str | None] = str             # str is assignable to str | None
bad1: TypeForm[str | None] = str | int     # int is not
bad2: TypeForm[object] = (1, 2)                    # a tuple expression is not a type expression
bad3: TypeForm[object] = ClassVar[int]             # qualifiers are not types
bad4 = TypeForm(type(1))                   # calls are not allowed in type expressions
n: int = checkcast(str, "x")               # the form says str, so the result is str

Reading it

  • Inference flows from the form. Both checkers solve T = list[int] | None from the union, Literal['r', 'w'] from the literal, and int from Annotated[int, "1-65535"], because metadata is ignored, as the PEP permits. mypy prints the literal as Literal['r'] | Literal['w'] and pyright prints it as Literal['r', 'w']. They are the same type.
  • Pydantic gets it for free. TypeAdapter.__init__ is now annotated type: TypeForm[T], so ta.validate_python("7") is int | str in both checkers. This is the change the pydantic 2.14 release notes call out: on 2.13 the result was Unknown. One caveat is that when pyright could not import pydantic (an earlier run without --pythonpath), the result silently fell back to Unknown. Always check that the library actually resolves.
  • type[T] really is too narrow. On lines 7 and 8 both checkers reject str | None and Literal["hi"] for the old type[T] signature. That is the exact motivating example of the PEP.
  • Assignability is about the spelled type. TypeForm[str | None] = str is accepted, because str is assignable to str | None. = str | int is rejected (line 11). Line 15 shows the payoff of a generic signature: checkcast(str, ...) returns str, so assigning it to int is an error.
  • The checkers do not agree on everything yet. pyright rejects ClassVar[int] as a type form (line 13, reportInvalidTypeForm). mypy 2.4.1 says nothing about it, even though the PEP lists ClassVar[int] among its invalid examples. Both reject TypeForm(type(1)). pyright emits two diagnostics (a type() call and “Call expression not allowed in type expression”), mypy says “TypeForm argument is not a type”. If your library depends on rejection, test it under every checker your users run.
  • The runtime is the same as before. TypeForm(dict[str, tuple[int, ...]]) printed dict[str, tuple[int, ...]], the very object passed in. The runtime column also shows the bugs a TypeForm signature does not catch. True is an int to isinstance, which is why the lab excludes bool explicitly. Literal[True] must not match 1, which is why it compares type(value) is type(a). Your interpreter of type forms still needs its own tests.

Pitfalls

  • Do not annotate introspection helpers with TypeForm. If the function must accept ClassVar[int], Final, Required[...] or InitVar, those are annotation expressions, not type expressions. Keep object there, as typing.get_args does.
  • Strings are type forms, but you have to evaluate them. "list[int]" is a valid TypeForm[list[int]] to the checker, but at runtime it is just a str. The lab evals it in a typing + builtins namespace. Real libraries resolve it in the caller’s module namespace, which is the hard part (see typing.evaluate_forward_ref / annotationlib in 3.15). Never eval untrusted input.
  • TypeForm is not type. You cannot call typx() or use isinstance(x, typx) on a TypeForm[T], because a union or literal is not a class. The checker treats it as having only object’s attributes. Branch on get_origin first and only call isinstance once you know it is a type.
  • Older Pythons. typing.TypeForm is new in 3.15. For 3.10–3.14 import it from typing_extensions, which is what pydantic does, and pin a checker new enough to understand it. The pydantic notes say pyright 1.1.412 and mypy 2.2 or later.
  • Bare TypeForm under --strict. mypy reports Missing type arguments for generic type "TypeForm". Write TypeForm[object] when you mean “any type form”.

Try this

  1. Add TypedDict support to is_assignable (use typing.is_typeddict and __required_keys__). Check that reveal_type after a successful check shows your TypedDict in both checkers.
  2. Write class Field[T]: def __init__(self, typx: TypeForm[T], default: T) -> None. Confirm that Field(int | None, "x") is rejected and Field(int | None, None) is accepted.
  3. Change checkcast’s parameter back to type[T] and record every line of demo.py that each checker now flags.
  4. Make the lab fail on ClassVar[int] at runtime as well, by rejecting get_origin(typx) is ClassVar. Then decide whether a runtime check should be stricter than mypy.
