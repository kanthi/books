system.nix: Channel-Free NixOS Entry Point

On NixOS 26.05 (“Yarara”) without flakes, the boring default is system.nix: pin nixpkgs with builtins.fetchTarball, evaluate a full NixOS system derivation, and let nixos-rebuild / nixos-install run with an empty NIX_PATH and without nix-channel. Keep configuration.nix as the module; put the pin and the import "${nixpkgs}/nixos" { … } call in system.nix. If the desk already uses flakes, keep flakes — system.nix is the boring non-flake pin path, not a second entry point beside flake.nix.

Targets: NixOS 26.05, Nix 2.35.x (2.35.2 current). Stable means nixos-26.05, not nixos-unstable.

Mental model

Three files, three jobs:

┌─────────────────────┐   ┌──────────────────────┐   ┌─────────────────────┐
│  configuration.nix  │   │     system.nix       │   │      flake.nix      │
│  NixOS *module*     │   │  system *entry*      │   │  flake *entry*      │
│  options + imports  │   │  pin nixpkgs + eval  │   │  inputs + outputs   │
│  does NOT pick pkgs │   │  → system derivation │   │  → nixosConfigurations│
└──────────┬──────────┘   └──────────┬───────────┘   └──────────┬──────────┘
           │                         │                          │
           └─────────► used by ◄─────┘                          │
                     nixos-rebuild / nixos-install              │
                     (ONE entry per desk) ◄─────────────────────┘
Concern configuration.nix system.nix (26.05+) flake.nix
What it is A NixOS module Expression → system derivation (or attrset of them) Flake with nixosConfigurations
Declares nixpkgs? No Yes (fetchTarball, etc.) Yes (inputs.nixpkgs)
Needs channel / NIX_PATH? Historically yes No — empty NIX_PATH is fine No
Default path /etc/nixos/configuration.nix /etc/nixos/system.nix /etc/nixos/flake.nix
Select host One module tree --attr when the file is an attrset #hostname
Other loaders — cwd system.nix with --attr; any path with --file --flake

Discovery (simplified): --file wins; with --attr, look for system.nix in the current directory (and nixos-system / /etc/nixos/system.nix defaults); otherwise /etc/nixos/system.nix when present. The file must evaluate to a NixOS system derivation, or an attribute set of such — then select with --attr.

Worked examples

Case 1: Minimal /etc/nixos/system.nix and switch

Desk host desk-workstation already has /etc/nixos/configuration.nix. Add the channel-free entry beside it. Use placeholders until you prefetch — do not paste invented hashes.

# system.nix
# /etc/nixos/system.nix — NixOS 26.05 desk-workstation
let
  # Pin to the nixos-26.05 channel tip. Refresh on the desk, then paste:
  #   curl -I https://channels.nixos.org/nixos-26.05
  #     → read the redirect / commit from the response headers
  #   nix-prefetch-url --unpack \
  #     https://github.com/NixOS/nixpkgs/archive/<COMMIT>.tar.gz
  #     → print sha256; substitute below
  nixpkgs = builtins.fetchTarball {
    url = "https://github.com/NixOS/nixpkgs/archive/<COMMIT>.tar.gz";
    sha256 = "<SHA256>";
  };
in
import "${nixpkgs}/nixos" {
  configuration = ./configuration.nix;
}
# configuration.nix
# /etc/nixos/configuration.nix — module only; no nixpkgs pin here
{ config, pkgs, ... }:

{
  imports = [ ./hardware-configuration.nix ];

  networking.hostName = "desk-workstation";

  environment.systemPackages = with pkgs; [
    git
    vim
    curl
  ];

  system.stateVersion = "26.05";
}
# switch-desk.sh
# Empty NIX_PATH is intentional — system.nix carries the pin.
export NIX_PATH=
sudo -E nixos-rebuild switch

Representative success shape (store paths and generation numbers vary):

…

# verify-entry.sh

readlink -f /run/current-system
26.05.YYYYMMDD.abcdef (Yarara)

Legacy nix-channel --list output is irrelevant once evaluation goes through system.nix.

Case 2: Attrset of hosts and --attr desk

One tracked system.nix can expose several machines. Each attribute must be a system derivation, not a bare module.

# system.nix
# ~/src/desk-nixos/system.nix — multi-host attrset
let
  nixpkgs = builtins.fetchTarball {
    url = "https://github.com/NixOS/nixpkgs/archive/<COMMIT>.tar.gz";
    sha256 = "<SHA256>";
  };
  nixos = configuration: import "${nixpkgs}/nixos" { inherit configuration; };
in
{
  desk = nixos ./hosts/desk-workstation/configuration.nix;
  lab = nixos ./hosts/lab-vm/configuration.nix;
}
# configuration.nix
# ~/src/desk-nixos/hosts/desk-workstation/configuration.nix
{ config, pkgs, ... }:

{
  imports = [ ./hardware-configuration.nix ];
  networking.hostName = "desk-workstation";
  system.stateVersion = "26.05";
}

Current-directory system.nix is picked up when --attr is set:

# rebuild-desk-attr.sh
cd ~/src/desk-nixos
export NIX_PATH=
sudo -E nixos-rebuild switch --attr desk

Or name the file:

# rebuild-desk-file-attr.sh
cd ~/src/desk-nixos
export NIX_PATH=
sudo -E nixos-rebuild switch --file ./system.nix --attr desk

Forgetting --attr on an attrset root fails along this shape:

error: … expected a NixOS system derivation at the root of the file,
       but got an attribute set; pass --attr <name> (e.g. --attr desk)

Installer uses the same contract:

# install-desk.sh
sudo nixos-install --root /mnt --file /mnt/src/system.nix --attr desk

Case 3: --file from a git checkout

Keep the pin in git; rebuild against the tracked tree (thin /etc/nixos or none).

# system.nix
# ~/src/desk-nixos/system.nix — single-host file entry
let
  nixpkgs = builtins.fetchTarball {
    url = "https://github.com/NixOS/nixpkgs/archive/<COMMIT>.tar.gz";
    sha256 = "<SHA256>";
  };
in
import "${nixpkgs}/nixos" {
  configuration = ./configuration.nix;
}
# rebuild-from-git.sh
cd ~/src/desk-nixos
git pull --ff-only
export NIX_PATH=
sudo -E nixos-rebuild switch --file "$PWD/system.nix"
building the system configuration from /home/kanthi/src/desk-nixos/system.nix...
these derivations will be built:
  /nix/store/…-nixos-system-desk-workstation-26.05….drv

Refresh the pin (replace placeholders in system.nix, commit, rebuild) — prefer this over nix-channel --update:

# refresh-pin.sh
curl -sI https://channels.nixos.org/nixos-26.05 | tr -d '\r' | grep -iE '^(HTTP|location|redirect|x-)'
# After extracting COMMIT from the redirect / channel metadata:
nix-prefetch-url --unpack \
  "https://github.com/NixOS/nixpkgs/archive/<COMMIT>.tar.gz"
path is '/nix/store/…-source'
<SHA256>

Case 4: Wire nix.nixPath + nixos-rebuild repl

system.nix removes channels for builds, but editors and older tools still read NIX_PATH. Wire three entries and keep the pin alive across GC (Discourse / rnhmjoj pattern):

# system.nix
# /etc/nixos/system.nix — pin + nix.nixPath + GC-safe symlink
let
  nixpkgs = builtins.fetchTarball {
    url = "https://github.com/NixOS/nixpkgs/archive/<COMMIT>.tar.gz";
    sha256 = "<SHA256>";
  };
in
import "${nixpkgs}/nixos" {
  configuration = {
    imports = [ ./configuration.nix ];

    nix.nixPath = [
      "nixos-config=${toString ./configuration.nix}"   # nixos-rebuild edit
      "nixos-system=${toString ./system.nix}"         # rebuild from any cwd
      "nixpkgs=/run/current-system/nixpkgs"           # same pin as the system
    ];

    system.systemBuilderCommands = "ln -s ${nixpkgs} $out/nixpkgs";
  };
}
# path-and-repl.sh
export NIX_PATH=
sudo -E nixos-rebuild switch
echo "nixpkgs -> $(readlink -f /run/current-system/nixpkgs)"
nixos-rebuild repl

nixos-rebuild repl works with system.nix:

Welcome to Nix 2.35.2. Type :? for help.
Loading system...
Added 6 variables: config, options, pkgs, system, vm, vmWithBootLoader

nix-repl> config.networking.hostName
"desk-workstation"

nix-repl> options.system.stateVersion.value
"26.05"

Plain nixos-option may still need nixos-config on NIX_PATH even when rebuild works:

# nixos-option-desk.sh
nixos-option networking.hostName
# If: file 'nixos-config' was not found in the Nix search path
nixos-option -I nixos-config=/etc/nixos/configuration.nix networking.hostName
Value:
"desk-workstation"

Home Manager standalone does not auto-inherit the system.nix pin. Keep -I nixpkgs=… or share nix.nixPath — do not claim HM reads system.nix.

Case 5: Flake desk — skip system.nix; one entry point only

If desk-workstation already builds with flakes, do not add a parallel system.nix. One entry point per machine.

# flake.nix
# ~/src/desk-nixos/flake.nix — flake desk; no system.nix beside this
{
  description = "desk-workstation (flakes; NixOS 26.05)";

  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-26.05";

  outputs = { self, nixpkgs }: {
    nixosConfigurations.desk-workstation = nixpkgs.lib.nixosSystem {
      system = "x86_64-linux";
      modules = [ ./configuration.nix ];
    };
  };
}
# flake-desk-rebuild.sh
cd ~/src/desk-nixos
sudo nixos-rebuild switch --flake .#desk-workstation
building the system configuration...
activating the configuration...

Do not also maintain /etc/nixos/system.nix “just in case” and alternate between bare nixos-rebuild switch and --flake .#desk-workstation. Two pins drift; generations disagree about which nixpkgs you meant. Choose flakes or system.nix for that desk.

The trap

Trap A — leave configuration.nix alone and keep nix-channel. The module never declares which nixpkgs builds the system. Channel tip moves; desks diverge. Fix: add system.nix with an explicit fetchTarball pin (or move the desk to flakes).

Trap B — invent a second entry on a flake desk. /etc/nixos/system.nix plus flake.nix means two pins and two rebuild habits. Prefer flakes if you already have them; use system.nix for channel-free evaluation without flakes.

Trap C — treat system.nix as a module, or forget --attr on an attrset. The file must evaluate to a system derivation (import "${nixpkgs}/nixos" { … } or eval-config), not to { imports = [ … ]; }. Multi-host files need --attr desk. Standalone Home Manager and raw nixos-option do not “just see” the pin without nix.nixPath / -I.

# Anti-pattern — module-shaped system.nix (fails the entry contract)
# system.nix
{
  imports = [ ./configuration.nix ];
  networking.hostName = "desk-workstation";
}
# Boring fix — pin + evaluate a system derivation
# system.nix
let
  nixpkgs = builtins.fetchTarball {
    url = "https://github.com/NixOS/nixpkgs/archive/<COMMIT>.tar.gz";
    sha256 = "<SHA256>";
  };
in
import "${nixpkgs}/nixos" {
  configuration = ./configuration.nix;
}

The boring rule

  • On non-flake NixOS 26.05 desks, use /etc/nixos/system.nix (or --file / --attr) to pin nixpkgs and evaluate the system; stop relying on nix-channel for rebuilds.
  • Keep configuration.nix as the module. Put the pin and import "${nixpkgs}/nixos" { … } only in system.nix.
  • Refresh pins with curl -I https://channels.nixos.org/nixos-26.05 and nix-prefetch-url --unpack; commit real <COMMIT> / <SHA256> — never invent hashes.
  • Wire nix.nixPath (nixos-config, nixos-system, nixpkgs=/run/current-system/nixpkgs) plus system.systemBuilderCommands so tools and GC behave.
  • Prefer nixos-rebuild repl over assuming nixos-option works without nixos-config; pass -I for standalone Home Manager.
  • One entry point per desk: flakes or system.nix, not both. Stay on nixos-26.05 unless you deliberately track unstable elsewhere.

Try this

  1. On a disposable 26.05 VM, add Case 1’s system.nix with a freshly prefetched nixos-26.05 commit. export NIX_PATH= and nixos-rebuild switch. Confirm nixos-version and that rebuild works with empty NIX_PATH.
  2. Convert the tree to Case 2’s attrset (desk + lab). Rebuild with --attr desk, then omit --attr once and read the error. Install a second VM with nixos-install --file … --attr lab.
  3. Clone the config to ~/src/desk-nixos and rebuild with --file "$PWD/system.nix" only. Change a package, commit, rebuild again. Run the Case 3 refresh-pin commands and bump the tarball once.
  4. Apply Case 4’s nix.nixPath wiring. Run nixos-rebuild repl and evaluate config.networking.hostName. Try nixos-option before and after -I nixos-config=…. Confirm /run/current-system/nixpkgs exists after switch.
  5. On a flake-based lab host, add a throwaway /etc/nixos/system.nix with a different commit than flake.lock, rebuild both ways once, compare nixos-version / store paths, then delete system.nix and write “one entry point” into the desk runbook.
