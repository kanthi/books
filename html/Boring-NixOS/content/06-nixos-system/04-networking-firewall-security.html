Networking, Firewall, and Security

Network configuration and iptables rules on Linux are often managed imperatively, leaving machines vulnerable when ad-hoc rules are forgotten after a reboot. The boring default of NixOS is: declarative networking with networking.firewall enabled by default, explicitly whitelisted ports, and NetworkManager or systemd-networkd.

Mental model

In NixOS: 1. Firewall by Default: networking.firewall.enable defaults to true. All incoming ports are closed unless explicitly opened. 2. Automatic Port Openings: Many standard NixOS service modules (services.openssh.enable, services.nginx.enable) offer options to automatically punch through the firewall. 3. Declarative Network Interfaces: Static IPs, bridges, VLANs, and DNS nameservers are declared in code. 4. NetworkManager vs systemd-networkd: - Use networking.networkmanager.enable = true; on developer laptops and workstations with shifting Wi-Fi connections. - Use networking.useNetworkd = true; on cloud instances and bare-metal production servers.

networking.firewall = {
  enable = true;
  allowedTCPPorts = [ 80 443 ];
  allowedUDPPorts = [ 51820 ]; # WireGuard
};

Worked examples

Case 1: Hardened Network Configuration

Save as networking_config.nix.

# networking_config.nix
{
  networking = {
    hostName = "desk-gateway";
    domain = "internal.corp";

    # Firewall configuration
    firewall = {
      enable = true;
      allowPing = false; # Drop ICMP pings
      allowedTCPPorts = [ 22 8080 ];
      allowedTCPPortRanges = [
        { from = 9000; to = 9010; }
      ];
    };

    # DNS configuration
    nameservers = [ "1.1.1.1" "8.8.8.8" ];
  };
}

This configuration blocks all unlisted ports, rejects ping requests, and pins DNS servers declaratively.

Case 2: WireGuard VPN Configuration

Declare an encrypted WireGuard tunnel cleanly in NixOS:

# wireguard.nix
{ pkgs, ... }:

{
  networking.wireguard.interfaces.wg0 = {
    ips = [ "10.100.0.2/24" ];
    listenPort = 51820;
    privateKeyFile = "/etc/secrets/wireguard.key";

    peers = [
      {
        publicKey = "xTqWP5s6V4BDNtG3...";
        allowedIPs = [ "10.100.0.1/32" ];
        endpoint = "vpn.desk.corp:51820";
        persistentKeepalive = 25;
      }
    ];
  };
}

The interface, encryption keys, and routing are brought up automatically by systemd upon boot.

The trap

Disabling the firewall globally (networking.firewall.enable = false;) during development troubleshooting and forgetting to re-enable it before deploying to production.

The fix: Open specific development ports explicitly with networking.firewall.allowedTCPPorts = [ 3000 ];.

The boring rule

  • Always keep networking.firewall.enable = true;.
  • Use NetworkManager on workstations; use systemd-networkd on servers.
  • Keep secret keys (like WireGuard private keys) in external files referenced by path (privateKeyFile), never hardcoded in Nix expressions.

Try this

  1. In networking_config.nix, add networking.firewall.trustedInterfaces = [ "lo" "tailscale0" ]; to trust loopback and VPN traffic while blocking public interfaces.
