Minimal ISO to a Desktop

Goal: Boot the NixOS 26.05 minimal ISO, install a flake-defined host named lab, and reach a Plasma session whose configuration lives in ~/nixos-config.

The install chapter is the map: firmware, disk, generate-config, credentials. This chapter is one run of that map with the flake present before the first reboot. Do it on a VM or a spare disk.

Important

The partition commands erase the chosen disk. lsblk first. If the name is not /dev/vda, change every line. This lab has no disk encryption. Encryption, Disko, and Home Manager come after the machine boots.

What you are building

Choice This lab
Media NixOS 26.05 minimal ISO, x86_64
Firmware UEFI, Secure Boot off
Disk virtio, seen as /dev/vda. 1 GB ESP, ext4 root, 8 GB swap
Flake input github:NixOS/nixpkgs/nixos-26.05
Host attr and hostname lab
User alice, in wheel and networkmanager
Repo ~/nixos-config
Desktop SDDM, Plasma 6, Firefox, added only after the console boot works

A graphical ISO (Calamares) will also give you a desktop. It writes a classic configuration.nix and no flake. Use it when you want a mouse. Use this chapter when the first generation should already be the flake you will keep.

VM size that matches the rest of the book: 8 GB RAM, 64 GB disk, 2 CPUs. Firmware UEFI. Virtio disk is fine; the commands below use /dev/vda. A SATA disk appears as /dev/sda. An NVMe disk appears as /dev/nvme0n1 with partitions nvme0n1p1 and so on. Take a snapshot only after the console login works, so a bad desktop rebuild is a restore.

Download the minimal ISO from nixos.org/download. Attach it as a virtual CD, or write it to a USB stick the way the manual describes. In firmware, pick a UEFI boot entry that does not enforce Secure Boot. The ISO and the systemd-boot you are about to install are not signed for it. The secure-boot chapter is where signing comes back.

Boot the installer

The first menu entry is the installer. You land as the user nixos with no password prompt. Take a root shell and read the disks:

sudo -i
lsblk -o NAME,SIZE,TYPE,FSTYPE,LABEL

A plugged-in Ethernet link is already up. On Wi-Fi, nmtui is the text menu. Confirm the clock if TLS later fails:

timedatectl

Partition, format, mount

ESP is 1 GB, not the manual’s 512 MB. Kernel generations live on that filesystem, and a full ESP is a later chapter you do not need on day one. Root is ext4. Swap is 8 GB at the end of the disk. Partition 1 is the ESP so the numbers match the role.

parted /dev/vda -- mklabel gpt
parted /dev/vda -- mkpart ESP fat32 1MB 1GB
parted /dev/vda -- set 1 esp on
parted /dev/vda -- mkpart root ext4 1GB -8GB
parted /dev/vda -- mkpart swap linux-swap -8GB 100%

mkfs.fat -F 32 -n ESP /dev/vda1
mkfs.ext4 -L lab /dev/vda2
mkswap -L swap /dev/vda3

mount /dev/disk/by-label/lab /mnt
mkdir -p /mnt/boot
mount -o umask=077 /dev/disk/by-label/ESP /mnt/boot
swapon /dev/disk/by-label/swap

parted mentions /etc/fstab. Ignore it. NixOS writes fileSystems from the hardware file. umask=077 keeps the ESP readable by root, which systemd-boot requires. findmnt /mnt and findmnt /mnt/boot should both succeed before you continue.

Let the installer describe the hardware

nixos-generate-config --root /mnt

That writes /mnt/etc/nixos/hardware-configuration.nix and a long configuration.nix. Keep the hardware file. It records the initrd modules for this disk, the UUIDs, and the boot-filesystem masks. Those UUIDs belong to this VM. Generating again on another disk replaces the file. Do not paste a hardware file from a write-up, including this one.

The generated configuration.nix is a commented tour. Read it once if you want the tour. Then remove it. With a flake, nothing loads that path, and a file you edit by habit will not change the system:

rm /mnt/etc/nixos/configuration.nix

nixos-generate-config --flake can also write a flake.nix. The one it writes follows nixos-unstable. You booted 26.05 media. Write the flake yourself so the input matches the ISO.

The flake that installs

Two files, next to the hardware file. The ISO has nano and vim.

/mnt/etc/nixos/flake.nix:

{
  description = "Lab host on NixOS 26.05";

  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-26.05";

  outputs = { nixpkgs, ... }: {
    nixosConfigurations.lab = nixpkgs.lib.nixosSystem {
      modules = [
        ./hardware-configuration.nix
        ./base.nix
      ];
    };
  };
}

nixos-rebuild selects the attribute whose name equals the hostname when you pass a directory and no #attr. networking.hostName below is lab for that reason.

/mnt/etc/nixos/base.nix:

{ pkgs, ... }:
{
  boot.loader.systemd-boot.enable = true;
  boot.loader.efi.canTouchEfiVariables = true;

  networking.hostName = "lab";
  networking.networkmanager.enable = true;
  time.timeZone = "UTC";

  users.users.alice = {
    isNormalUser = true;
    extraGroups = [ "wheel" "networkmanager" ];
  };

  nix.settings.experimental-features = [ "nix-command" "flakes" ];

  environment.systemPackages = with pkgs; [
    git
    vim
  ];

  system.stateVersion = "26.05";
}
Lines Why they are here
systemd-boot, EFI variables UEFI boot menu entry for this install
NetworkManager Same tool the installer used, so Wi-Fi credentials have somewhere to go
wheel sudo for alice
networkmanager alice may change networks
experimental-features Flakes stay marked experimental. Install and rebuild turn them on for themselves. A later nix flake update fails if the installed config never set this.
git, vim The repo move on first boot needs both
system.stateVersion Record of the release this machine was installed with. Leave it when you later change the nixpkgs input.

No password in the Nix file. You set that in the next two commands, on the machine, where passwords belong.

Lock, then install

nix --extra-experimental-features "nix-command flakes" \
  flake lock /mnt/etc/nixos
nixos-install --flake /mnt/etc/nixos#lab

flake lock writes flake.lock so the install builds one nixpkgs commit, the 26.05 branch tip that existed when you locked. The branch keeps moving after that. Your lock does not.

The installer asks for a root password at the end. Store it. You use it when alice cannot get in.

If the install complains about a NAR hash

nixos-install fingerprints the config directory, and it also creates flake.lock inside that directory while doing so. The second step changes the tree the first step hashed, and Nix stops with a NAR hash mismatch on path:/mnt/etc/nixos. You did not corrupt the files.

Locking first, as above, keeps the fingerprint stable. If you already hit the error, run nixos-install again. The lock file is on disk now, so the second fingerprint includes it. Other ISO builds may lock without tripping. Locking yourself means you do not depend on which build you downloaded.

Set alice’s password, then power off

nixos-enter --root /mnt -c 'passwd alice'
poweroff

nixos-enter is a chroot that also sets up what NixOS tools expect. The account exists from users.users.alice. The password does not, until this command. Nothing in ~/nixos-config will ever contain it.

Detach the ISO before the next start. On hardware, reboot and remove the USB stick.

If a later generation will not boot, the recovery path is the same ISO: mount the labels on /mnt and /mnt/boot, then nixos-enter. You are back in the installed system with its store.

First boot: own the files

One systemd-boot entry, then a text login. alice and the password from passwd. If Wi-Fi worked in the installer and the installed system is offline, run nmtui once. The installed system does not inherit the installer’s saved networks.

/etc/nixos is root-owned. Copy it into the home directory, give it to alice, and make a git repo with a repo-local identity:

sudo cp -a /etc/nixos ~/nixos-config
sudo chown -R "$USER:$USER" ~/nixos-config
cd ~/nixos-config
git init
git config user.name alice
git config user.email alice@lab.invalid
git add .
git commit -m "Install lab on 26.05"

git config without --global stays inside this repo. Leave /etc/nixos in place until the desktop generation has booted. After that, delete it so the next edit is not the stale copy.

From here the flake Nix sees is ~/nixos-config. In a git checkout, Nix copies tracked files only.

Add a desktop as its own module

~/nixos-config/desktop.nix:

{ ... }:
{
  services.displayManager.sddm.enable = true;
  services.desktopManager.plasma6.enable = true;
  programs.firefox.enable = true;
}

Register it in flake.nix:

      modules = [
        ./hardware-configuration.nix
        ./base.nix
        ./desktop.nix
      ];

Those two service options pull in SDDM on Wayland, PipeWire, and a Plasma session, including a terminal and a network icon when NetworkManager is enabled. Firefox is an explicit program. Removing the desktop later is one line in the module list.

boot installs the generation and selects it for the next start. The system you are logged into keeps running. That is the right verb for a change the size of a desktop. Later, everyday edits use switch.

cd ~/nixos-config
git add desktop.nix flake.nix
nixos-rebuild boot --flake ~/nixos-config#lab --sudo

--sudo builds as alice and elevates for the activation. The git repo is in a home directory, so a plain sudo nixos-rebuild is the command that fights file ownership. #lab makes the attribute obvious. Once hostname prints lab, --flake ~/nixos-config selects the same attribute.

The git add is load-bearing

Skip it and the rebuild errors with a path that is “not tracked by Git”, and the message names desktop.nix. Stage the file. A commit can wait until the generation boots. Edits to a file that is already tracked are visible to Nix before you commit them. New files are invisible until git add.

The desktop build is the long download. When it finishes:

reboot

The menu has two entries. The higher generation is Plasma and is the default. The lower one is the console system from the install. If SDDM never appears, boot the older entry. You are on the closure that worked, with the repo still in home.

Log in, open a terminal, and commit while you know this generation is good:

cd ~/nixos-config
git commit -am "Plasma desktop on lab"

The loop

File Owns
flake.nix nixpkgs 26.05, the lab attribute, the module list
flake.lock The nixpkgs commit
base.nix Boot loader, hostname, NetworkManager, alice, packages, stateVersion
hardware-configuration.nix This disk and this firmware
desktop.nix SDDM, Plasma 6, Firefox

Passwords, the Wi-Fi secret NetworkManager stored, and the contents of /home/alice are on the machine. They are not in the five files.

  1. Edit ~/nixos-config.
  2. git add any new file.
  3. nixos-rebuild switch --flake ~/nixos-config#lab --sudo
  4. When it behaves, git commit.

A program goes in environment.systemPackages. An option you do not know yet is on search.nixos.org/options, searched from the 26.05 channel.

An update inside the release is two commands in the repo:

nix flake update nixpkgs
nixos-rebuild switch --flake ~/nixos-config#lab --sudo
git add flake.lock
git commit -m "Update nixpkgs within 26.05"

The ref stays nixos-26.05. The lock moves. When 26.11 is released, change the ref, update, rebuild, and leave system.stateVersion at "26.05".

When it breaks

Symptom What happened What you do
“not tracked by Git” A new file was never staged git add the path Nix printed
A long eval error The last lines name your file A missing semicolon is the usual cause
Desktop never comes up Generation 2 failed at runtime Boot generation 1 from the menu
switch booted a bad config The new closure is active nixos-rebuild switch --rollback --sudo

Rollback changes which closure is running. It does not change ~/nixos-config, and it does not undo a data migration a service already performed. After a rollback, revert or fix the commit. The next rebuild will build whatever the repo says.

nixos-rebuild switch --rollback is the running system. The boot menu is the system you can still reach when the running one does not start. Both are reasons to use boot for the desktop step and switch afterwards.

Where this book goes next

  • Users and SSH keys, so the password is the break-glass path.
  • Home Manager, for the shell and editor, in the home-and-flake part.
  • Disko, when the next install should partition from the repo.
  • A second nixosConfigurations attribute, when a second machine should share base.nix.

Push ~/nixos-config somewhere you can clone. A reinstall is then: partition, mount, clone onto /mnt/etc/nixos, replace hardware-configuration.nix with nixos-generate-config --root /mnt --show-hardware-config, lock if the lock is already in the clone, nixos-install --flake /mnt/etc/nixos#lab. Passwords and home directories still need their own copy.
