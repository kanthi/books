# CI on a pull request

One language, one repo: **desk-tickets**, Python 3.14, `pytest` and `ruff`. The job must run on `pull_request` so a fork cannot skip it, and on `push` to `main` so merge still has a check.

This is not a testing textbook. The workflow is the point.

## Repo

```text
desk-tickets/
├── pyproject.toml
├── src/tickets/__init__.py
├── tests/test_ping.py
└── .github/workflows/ci.yml
```

```toml
# pyproject.toml
[project]
name = "desk-tickets"
version = "0.1.0"
requires-python = ">=3.14"
dependencies = []

[project.optional-dependencies]
dev = ["pytest>=8", "ruff>=0.11"]

[tool.pytest.ini_options]
pythonpath = ["src"]

[tool.ruff]
target-version = "py314"
src = ["src", "tests"]
```

```python
# src/tickets/__init__.py
def ping() -> str:
    return "ok"
```

```python
# tests/test_ping.py
from tickets import ping


def test_ping() -> None:
    assert ping() == "ok"
```

## Workflow

```yaml
# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]
  pull_request:

permissions:
  contents: read

concurrency:
  group: ci-${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: actions/setup-python@5fda3b95a4ea91299a34e894583c3862153e4b97 # v7.0.0
        with:
          python-version: "3.14"
          cache: pip
          cache-dependency-path: pyproject.toml
      - name: Install
        run: pip install -e ".[dev]"
      - name: Lint
        run: ruff check src tests
      - name: Test
        run: pytest -q
```

`concurrency` cancels the previous run on the same branch when you push again. That is Operate; it belongs on CI from day one so you do not pay for stale commits.

`cache: pip` is enough. Do not add `actions/cache` until this is slow.

Install with the same extra the developer uses (`[dev]`). A CI image that only has pytest and not ruff is a different project than the laptop.

## Required check

On the repo: **Settings → Rulesets** (or classic branch protection) → require the check named `test` (the **job** id, unless you set `name:`). Path filters that skip the workflow will leave that check Pending — keep this workflow on every PR that can merge to `main`.

## What not to add yet

- Codecov and Slack actions from a marketplace README. Coverage XML as an **artifact** is enough until you have a coverage product you trust, pinned by SHA.
- Deploy jobs in the same file. CI fails closed; deploy is a different workflow with an environment.
- `pull_request_target`. You do not need secrets to run pytest.

## Try this

1. Push this tree. Open a PR that breaks `test_ping`. Confirm the check is red and merge is blocked once the job is required.
2. Fix the test, push, confirm the new run cancels the old one (`concurrency`).
3. Add a second Python in a matrix (`3.13`, `3.14`) with `fail-fast: false`. Keep lint on one cell only (`if: matrix.python == '3.14'`).
